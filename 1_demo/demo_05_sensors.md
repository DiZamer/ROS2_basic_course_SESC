# Демонстрация: датчики — виртуальные и реальные сенсоры

## Цель

Показать путь «физическая величина → сенсор → данные → потребитель» и то, что виртуальный сенсор в Gazebo отдаёт те же типы данных, что и реальный. Практически: увидеть устройства глазами Linux (`lsusb`, `ls /dev`, `i2cdetect`) и «подслушать» лидар TIAgo в симуляции (`ros2 topic echo`).

## Подготовка до занятия

1. Dev Container уровня 2 открыт и готов (`.devcontainer/`, Ubuntu 24.04 + ROS2 Jazzy).
2. Заранее проверены `lsusb`, `ls /dev` (в контейнере без проброшенного железа список короткий — это нормально).
3. Для кейса уровня 3 — симуляция TIAgo готова к запуску, либо подготовлен план Б.
4. Подготовлена таблица датчиков из [`../2_knowledge/sensors.md`](../2_knowledge/sensors.md).

## Контейнер

- Уровень 2: Dev Container `.devcontainer/` — `lsusb`, `ls /dev`, `i2cdetect` (железо в контейнере обычно не видно — это часть объяснения).
- Уровень 3: контейнер `3_Robot/TIAgo_humble/` — запуск симуляции и чтение `/scan_front_raw`.

## Контекст для студентов

> «Робот не видит комнату напрямую — он читает показания датчиков. Сенсор превращает физическую величину в числа: расстояние, свет, ускорение. А виртуальный сенсор в Gazebo считает то же самое по модели мира, поэтому на нём можно учиться до покупки железа.»

## Что показать

### 1. Путь данных и типы датчиков

Показать схему «физическая величина → сенсор → данные → потребитель» и таблицу:

| Датчик | Что измеряет | Данные | Частота |
| --- | --- | --- | --- |
| LiDAR | расстояние по углам | массив дальностей `ranges[]` | 10–20 Гц |
| RGB-камера | изображение | кадр из пикселей | 15–30 кадров/с |
| IMU | ускорение, поворот | угловая скорость, ускорение | 100–400 Гц |
| Энкодер | вращение колеса | счётчик оборотов / скорость | 100–1000 Гц |

**Что сказать**: «Сенсоры — органы чувств робота: камера — глаза, IMU — вестибулярный аппарат, дальномер — рука. Частота — сколько раз в секунду сенсор выдаёт значение: 10 Гц = 10 раз в секунду.»

### 2. Виртуальный vs реальный

Показать описание лидара в Gazebo (SDF) и объяснить, что `update_rate` задаёт частоту:

```xml
<sensor name="gpu_lidar" type="gpu_lidar">
  <topic>lidar</topic>
  <update_rate>10</update_rate>
  <ray>
    <scan>
      <horizontal>
        <samples>640</samples>
        <min_angle>-1.396263</min_angle>
        <max_angle>1.396263</max_angle>
      </horizontal>
    </scan>
    <range>
      <min>0.08</min>
      <max>10.0</max>
    </range>
  </ray>
  <always_on>1</always_on>
</sensor>
```

**Что сказать**: «Реальный лидар измеряет расстояние лазером, виртуальный считает пересечение луча со стеной в симуляции. Разница только в шаге измерения — тип данных одинаковый. Программе-потребителю всё равно.»

### 3. Устройства глазами Linux

```bash
sudo apt install -y usbutils i2c-tools
lsusb
ls /dev
i2cdetect -l
i2cdetect -y 1
```

**Что сказать**: «Реальный датчик в Linux — это файл в `/dev` (`ttyUSB*`, `video*`, `i2c-*`) или адрес на шине I2C. `lsusb` — список USB-устройств, `i2cdetect -y 1` — адреса датчиков на шине. В контейнере без проброшенного железа списки короткие — это нормально.»

### 4. Кейс робота: подслушать лидар (уровень 3)

В симуляции:

```bash
ros2 launch tiago_gazebo tiago_gazebo.launch.py is_public_sim:=True
# в другом терминале:
ros2 topic list | grep scan
ros2 topic echo /scan_front_raw --once
ros2 topic hz /scan_front_raw
```

**Что сказать**: «`echo --once` печатает массив дальностей `ranges[]` — данные лидара. `hz` показывает ~10 Гц, что совпадает с `update_rate` в описании сенсора. Полный разбор `ros2 topic` — на занятии 9.»

### 5. Смелый тест: ослепить навигацию (этап 3, реальный ровер)

На реальном ровере MentorPi M1 перекрыть лидар ладонью и наблюдать, как меняются дальности в `/scan` на ближних углах.

**Что сказать**: «Данные сенсора — это физика, а не абстракция: дальности в перекрытом секторе резко уменьшаются. На занятии 5 — демонстрация инструктора, выполняется на занятиях 25–30.»

## Что сказать

- «Робот видит мир только через сенсоры — как мы через органы чувств.»
- «Виртуальный сенсор даёт те же данные, что и реальный. Потребителю всё равно.»
- «Частота — сколько раз в секунду сенсор выдаёт значение. Лидар — 10 Гц, IMU — сотни Гц.»
- «Эти данные в занятиях 6–9 станут узлами, публикующими данные в темы.»

## Ожидаемый результат

- `lsusb` показывает USB-устройства (в контейнере список может быть коротким).
- `ls /dev` — студент называет `ttyUSB*`/`video*`/`i2c-*`.
- `i2cdetect -l` показывает шины или объясняется, почему их нет в контейнере.
- `ros2 topic echo /scan_front_raw --once` печатает `ranges[]`; `hz` показывает ~10 Гц.

## Типичные проблемы

| Симптом | Причина | Исправление |
| --- | --- | --- |
| `lsusb: command not found` | Не установлен `usbutils` | `sudo apt install -y usbutils` |
| `i2cdetect -y 1` → «No such file» | В контейнере нет шины I2C | Это нормально: шины есть на реальном Raspberry Pi |
| `ros2 topic` не видит `/scan_front_raw` | Симуляция не запущена или другой лидар | Запустить `tiago_gazebo`, проверить `ros2 topic list` |
| Студент ждёт датчики робота в контейнере уровня 2 | Железо не проброшено в контейнер | Датчики видно там, где они физически подключены |
