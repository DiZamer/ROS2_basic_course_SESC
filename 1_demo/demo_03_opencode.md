# Демонстрация: агентная инженерия с opencode

## Цель

Показать, как opencode работает по текстовому запросу, чем агент Plan отличается от Build, какие права у агента (`permission`), и как проверить, что агент не выдумывает несуществующие файлы. В финале — opencode читает и объясняет структуру кода TIAgo.

## Подготовка до занятия

1. opencode установлен и настроен провайдер модели (`opencode auth login` выполнен).
2. Открыта папка проекта `ROS2_basic_course_SESC`.
3. Заранее проверены `opencode --version` и `opencode agent list`.
4. Подготовлен один read-only запрос, ответ на который уже сверен с фактическими файлами.

## Контейнер

- opencode — отдельный инструмент; в курсе запускается на хосте (не в контейнере курса).
- Читает проект `ROS2_basic_course_SESC/`, включая код робота в `3_Robot/TIAgo_humble/`.
- ROS2 на хост не ставится: opencode читает файлы, а ROS2-команды выполняются только внутри контейнеров.

## Контекст для студентов

> «Агент — стажёр с отличной памятью, который работает в вашей папке. Он ускоряет рутину, но может ошибаться. Поэтому вы даёте ему письменные правила (`AGENTS.md`) и права (`permission`), а каждый ответ проверяете. На зачёте отвечаете вы, а не агент.»

## Что показать

### 1. Проверить opencode

```bash
opencode --version
opencode agent list
```

**Что сказать**: «Состав агентов зависит от версии, конфигурации и подключённых проектных агентов. Посмотрим реальный список, затем проверим, какие права назначены выбранному агенту.»

### 2. Права агента

Открыть `opencode.jsonc` и показать блок `permission`:

```jsonc
"permission": {
  "edit": "allow",
  "bash": { "*": "ask", "ls": "allow" },
  "webfetch": "ask",
  "read": "allow",
  "grep": "allow",
  "glob": "allow"
}
```

**Что сказать**: «`allow` — разрешить, `ask` — запросить подтверждение, `deny` — запретить. Здесь edit разрешён, а Bash-команды требуют подтверждения, кроме `ls`. Эффективные права выбранного агента могут включать и другие настройки — прочитайте их до запуска.»

### 3. Read-only запрос через Plan

```bash
opencode run --agent plan "Объясни структуру репозитория: за что отвечают папки 1_lecture, 2_knowledge, 2_practice, 2_homework, 3_Robot"
```

**Что сказать**: «Plan не меняет файлы — для разбора кода берём его, а не Build. Build может предложить и применить правки.»

### 4. Кейс робота: проверить, не выдумывает ли агент (уровень 3)

```bash
opencode run --agent plan "Перечисли пакеты в 3_Robot/TIAgo_humble/ros2_ws/src и за что отвечает tiago_description"
```

Затем сверить с фактом:

```bash
ls 3_Robot/TIAgo_humble/ros2_ws/src
ls 3_Robot/TIAgo_humble/ros2_ws/src/tiago_robot/tiago_description
```

**Что сказать**: «Агент может назвать несуществующий пакет. Ответ всегда сверяем с `ls` и документацией. Совпало — доверяем, нет — нашли галлюцинацию.»

### 5. Проверить ответ и отсутствие изменений

```bash
git -C 3_Robot/TIAgo_humble status --short
git status --short
```

**Что сказать**: «Сверяем состояние репозитория после read-only анализа. Не сравниваем Plan и Build на рабочей копии TIAGo и не используем `git restore`: он может удалить чужие незакоммиченные изменения.»

## Что сказать

- «Сначала понимание, потом ускорение. Агент — инструмент, как `colcon` или `git`.»
- «`AGENTS.md` — письменные правила для агента. Без него он действует хаотично.»
- «Агент не заменяет знание ROS2. Он может ошибаться в командах — проверяйте результат.»
- «Не отправляйте агенту секреты и не разрешайте `rm -rf` без проверки.»

## Ожидаемый результат

- `opencode agent list` показывает встроенных и проектных агентов.
- Студент объясняет блок `permission` из `opencode.jsonc`.
- Read-only запрос через Plan даёт ответ без изменений в проекте.
- Сверка с `ls` подтверждает (или опровергает) список пакетов TIAgo.

## Типичные проблемы

| Симптом | Причина | Исправление |
| --- | --- | --- |
| `opencode: command not found` | opencode не установлен | Установить по [официальной инструкции](https://opencode.ai/docs/) |
| Нет модели/провайдера | Не выполнен `opencode auth login` | `opencode auth login` и выбрать провайдера |
| Агент начал менять файлы | Работа в Build, а не в Plan | Переключиться на Plan (Tab) или `--agent plan` |
| Агент выдумал файлы | Запрос слишком общий | Спросить про конкретный файл и сверить с `ls` |

## План Б

Если opencode недоступен (нет модели/провайдера):

1. Показать скриншоты/пример диалога и разобрать структуру ответа.
2. Показать `opencode.jsonc` и `AGENTS.md` как текст — объяснить `permission` и правила.
3. Показать структуру `ros2_ws/src/` через `ls` и объяснить назначение пакетов вручную.
4. Если не работает только у части студентов — выполнить `opencode auth login` и выбрать провайдера.
