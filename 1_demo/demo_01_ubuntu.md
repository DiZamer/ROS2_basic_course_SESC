# Демонстрация: Ubuntu и командная строка

## Цель

Показать, что терминал — основной способ управления роботом: перемещение по файловой системе (`pwd`, `ls`, `cd`), права и `sudo`, установка пакетов через `apt`, чтение справки (`--help`, `man`), переменная `PATH` и удалённое подключение по SSH. В финале — показать, что установленный ROS2 — это обычные файлы в `/opt/ros/`, и разобрать два разных отказа SSH.

## Подготовка до занятия

1. Открыт и собран Dev Container уровня 2 (`.devcontainer/`, Ubuntu 24.04 + ROS2 Jazzy).
2. Терминал в VS Code открыт, приглашение показывает `ubuntu@...`.
3. Заранее проверены `pwd`, `whoami`, `sudo apt update` (беспарольный sudo в контейнере).
4. Если планируется кейс уровня 3 — контейнер `3_Robot/TIAgo_humble/` готов или подготовлен план Б.

## Контейнер

- Уровень 2: Dev Container `.devcontainer/` (Ubuntu 24.04 + ROS2 Jazzy) — основная часть.
- Уровень 3: контейнер `3_Robot/TIAgo_humble/` (ROS2 Humble) — кейс «ROS2 — это файлы» и разбор отказов SSH.

## Контекст для студентов

> «Робот — это компьютер без графики. Его настраивают, запускают и отлаживают командами, а не мышью. Сегодня мы научимся говорить с компьютером короткими командами — это база для всего курса, потому что все инструменты ROS2 запускаются из терминала.»

## Что показать

### 1. Навигация и файлы

```bash
pwd
whoami
mkdir -p ~/demo_cli && cd ~/demo_cli
touch notes.txt
ls -la
cat /etc/os-release
```

**Что сказать**: «`pwd` — где я, `whoami` — кто я (пользователь `ubuntu`, не root). `ls -la` показывает и скрытые файлы. `cat /etc/os-release` говорит, что это Ubuntu 24.04. Файловая система — дерево с корнем `/`, а ваша папка — `~`.»

### 2. Права и sudo

```bash
chmod +x notes.txt
ls -l notes.txt
sudo apt update
```

**Что сказать**: «`-rwxr-xr-x` — три пары прав: владелец, группа, остальные. `sudo` даёт временные права администратора. Постоянно под root не работаем: случайная ошибка сломает систему.»

### 3. Пакеты и справка

```bash
sudo apt install -y tree
tree -L 2 ~
tree --help
```

**Что сказать**: «`apt` — магазин программ. `--help` и `man` — два способа спросить, как пользоваться программой. Из `man` выходят клавишей `q`.»

### 4. PATH и переменные окружения

```bash
echo $PATH
which bash
export ROBOT_NAME=tiago
echo $ROBOT_NAME
```

**Что сказать**: «`PATH` — список папок, где shell ищет программы. `which bash` показывает, откуда запускается bash. `export` задаёт переменную для текущей сессии.»

### 5. SSH: ключи и подключение к локальному хосту

```bash
ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519
sudo apt install -y openssh-server
sudo service ssh start
cat ~/.ssh/id_ed25519.pub >> ~/.ssh/authorized_keys
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
ssh -o StrictHostKeyChecking=accept-new localhost
# внутри: hostname, затем exit
```

**Что сказать**: «SSH — дверь в другую машину. IP — номер дома, порт — квартира, ключ — ключ от двери. Публичный ключ кладут на машину, приватный хранят у себя и никому не показывают.»

### 6. Кейс робота: ROS2 — это файлы (уровень 3)

В контейнере робота:

```bash
cd /opt/ros/humble
pwd
ls
du -sh /opt/ros/humble
cd ~
```

**Что сказать**: «ROS2 — это обычные файлы на диске. По ним можно безопасно „гулять“. `du -sh` покажет объём установленного ROS2 Humble, `cd ~` вернёт домой — ничего не менялось.»

### 7. Кейс робота: разбор отказов SSH

```bash
ssh student@localhost -p 2222   # порт, на котором никто не слушает
```

**Что сказать**: «`Connection refused` — сервер не запущен или не тот порт. `Permission denied` — публичный ключ не на целевой машине. Это разные отказы, и у каждого своя причина.»

## Что сказать

- «Терминал — разговор с компьютером короткими командами вместо кликов мышью.»
- «`rm` удаляет навсегда, без корзины. Проверяйте путь перед удалением.»
- «`sudo` — временные права администратора, а не способ навигации: `sudo cd` не работает.»
- «Все инструменты ROS2 запускаются из этой же командной строки — мы начнём с занятия 6.»

## Ожидаемый результат

- `pwd` → `/home/ubuntu`, `whoami` → `ubuntu`.
- `sudo apt update` завершается без ошибки; `tree` устанавливается и печатает дерево папок.
- `which bash` → `/usr/bin/bash`; `echo $ROBOT_NAME` → `tiago`.
- `ssh localhost` входит по ключу без пароля; `hostname` показывает имя контейнера.
- В контейнере робота `du -sh /opt/ros/humble` показывает объём ROS2; `ssh ... -p 2222` выдаёт `Connection refused`.

## Типичные проблемы

| Симптом | Причина | Исправление |
| --- | --- | --- |
| `sudo apt update` просит пароль | sudo не настроен беспарольно | Проверить `Dockerfile`/`devcontainer.json` на настройку `NOPASSWD` |
| `bash: tree: command not found` | Пакет не установлен | `sudo apt install -y tree` |
| `Permission denied` при `ssh localhost` | Публичный ключ не в `authorized_keys` | Повторить `cat ... >> authorized_keys` и `chmod 600` |
| `Connection refused` при `ssh` | `sshd` не запущен | `sudo service ssh start` |
| `man tree` не работает | Пакет `man` не установлен | `sudo apt install -y man-db` |
