# Домашнее задание 3: первый запрос к opencode и дневник наблюдений

## Цель

Инициализировать opencode в своём клоне, изучить `AGENTS.md` проекта, выполнить разобранный запрос к агенту и зафиксировать в дневнике 2–3 примера задач, где агент ускоряет работу и где ошибается.

## Связь с темой занятия

Занятие 3 дало инструмент-ускоритель: агент, которым управляют через `AGENTS.md` и `permission`. Дома студент настраивает opencode в своём клоне, пробует его на реальной задаче и учится видеть, где агенту можно доверять, а где — нет.

## Предварительные требования

- Клонирован проект и открыт Dev Container уровня 2 (см. [`hw_02_setup.md`](hw_02_setup.md)).
- opencode установлен и настроен провайдер модели (`opencode auth login`).
- Понятия агента, permission и `AGENTS.md` — [`../2_knowledge/opencode_agent.md`](../2_knowledge/opencode_agent.md).

## Шаг к виртуальной модели робота

Задание не добавляет элемент модели, а готовит инструмент, которым студент будет пользоваться при сборке модели (начиная со занятия 4). Параллельно заводится дневник разработки в `~/my_robot/`, куда дальше записываются решения.

## Шаги

### Шаг 1. Проверить opencode в своём клоне

```bash
opencode --version
opencode agent list
```

Ожидаемый результат: версия без ошибки и список агентов.

### Шаг 2. Изучить AGENTS.md проекта

Прочитайте [`AGENTS.md`](../../AGENTS.md) в корне проекта и выпишите:

- главную цель проекта;
- правила стиля и работы с кодом;
- обязательные документы.

Ожидаемый результат: вы можете объяснить, какие правила получит агент в этом проекте.

### Шаг 3. Выполнить разобранный запрос

Сделайте read-only запрос через агента Plan и разберите ответ:

```bash
opencode run --agent plan "Объясни, как в этом проекте устроены три уровня материала (уровень 1, 2, 3) и где лежат практики и домашние задания"
```

Проверьте ответ по фактическому содержимому папок: совпадает ли с `ls 2_practice`, `ls 2_homework`.

### Шаг 4. Завести дневник разработки

В репозитории своей модели (созданном в `hw_02_setup.md`) заведите `diary.md`:

```bash
cd ~/my_robot
printf '# Дневник разработки\n\n' > diary.md
```

### Шаг 5. Зафиксировать 2–3 примера

Запишите в `diary.md` два списка по итогам наблюдений:

- **Где агент ускоряет** — 2–3 задачи, где ответ агента сэкономил время (объяснение структуры, поиск файла, шаблон кода).
- **Где агент ошибается** — 2–3 случая, где ответ был неточен или неверен, и как вы это обнаружили.

Пример записи:

```text
## Наблюдения за opencode

Ускоряет:
- объяснил назначение папок курса за один запрос;
- нашёл, где заданы права агента (opencode.jsonc).

Ошибается:
- назвал несуществующий файл практики — сверил с ls;
- предложил устаревшую команду — проверил по --help.
```

## Ожидаемый результат

- opencode запускается в клоне, `agent list` показывает агентов.
- Студент пересказывает назначение `AGENTS.md` и блока `permission`.
- Выполнен один разобранный read-only запрос; ответ сверен с файлами.
- В `~/my_robot/diary.md` записаны примеры «ускоряет» и «ошибается».

## Вопросы для самопроверки

1. Что произойдёт с агентом, если удалить `AGENTS.md` из проекта?
2. Почему для разбора кода берут Plan, а не Build?
3. Как понять, что агент выдумал несуществующий файл?
4. В чём польза дневника: почему важно фиксировать и удачи, и ошибки агента?

## Критерии оценки

Задание выполнено, если:

- `opencode --version` и `opencode agent list` работают;
- студент объясняет назначение `AGENTS.md` и блока `permission` из `opencode.jsonc`;
- выполнен и разобран read-only запрос (ответ сверен с фактическими файлами);
- в `~/my_robot/diary.md` есть записи с примерами «ускоряет» и «ошибается».

## Типичные ошибки

| Симптом | Причина | Исправление |
| --- | --- | --- |
| opencode не находит модель | Не выполнен `opencode auth login` | `opencode auth login` и выбрать провайдера |
| Агент меняет файлы без спроса | Работа в Build с `edit: allow` | Для анализа — Plan; перед правками читать `permission` |
| Ответ принят без проверки | Доверие «на слово» | Сверять с `ls`, `cat` и документацией |
| Дневник пустой | Забыли записать наблюдения | Добавить конкретные примеры, а не общие слова |
