# Домашняя работа-v2 02: домашнее окружение и первый коммит модели

> Продолжение занятия 2. ROS 2 работает в Dev Container, а не устанавливается на хост. Работа добавляет к будущей модели робота личный репозиторий и начальную историю.

## Цель

Дома открыть учебный проект в том же контейнерном окружении, проверить ROS 2 и создать отдельный репозиторий `~/my_robot/` с описанием робота, правилами `.gitignore` и первым коммитом.

## Связь с занятием

На занятии студент различал среду контейнера и историю проекта. В этой работе он проверяет обе части:

- Dev Container предоставляет инструменты курса;
- личный Git-репозиторий сохраняет исходную идею собственного робота.

Следующие домашние работы будут добавлять в историю пакет, узлы, сенсоры, управление и симуляцию.

## Предварительные требования

- Git, Docker и VS Code с расширением Dev Containers установлены по инструкции [`../2_knowledge/home_setup.md`](../2_knowledge/home_setup.md).
- Учебный проект склонирован; известен URL репозитория курса.
- Доступен общий Dev Container уровня 2 с ROS 2 Jazzy и Ubuntu 24.04.
- Для Windows используется WSL2/Docker Desktop либо другой путь из домашней инструкции.
- ROS 2 на хост не устанавливается.

## Ожидаемый результат

- Учебный проект открыт в Dev Container уровня 2.
- `ros2 --help` и узел `talker` работают внутри контейнера.
- В `~/my_robot/` есть `README.md`, `.gitignore` и первый коммит в ветке `main`.
- Студент может объяснить, где хранятся файлы и какие папки игнорируются.

## Шаг к виртуальной модели робота

Модель пока не описывается в URDF. Сначала студент фиксирует короткое техническое задание: тип базы, сенсоры и предполагаемое назначение. Это «нулевая версия» проекта, к которой последующие задания добавят ROS-пакеты, узлы, интерфейсы и геометрию.

## Шаг 1. Открыть учебный проект в контейнере

Откройте в VS Code папку уже склонированного проекта курса. Если VS Code запущен из терминала, перейдите в корень проекта и выполните:

```bash
code .
```

Затем выполните **Dev Containers: Reopen in Container**. При изменении Dockerfile или конфигурации используйте **Dev Containers: Rebuild Container**. Если проект ещё не склонирован, используйте реальный URL курса из LMS и инструкцию [`home_setup.md`](../2_knowledge/home_setup.md).

Если общий `.devcontainer/` ещё не включён в выданную копию курса, не устанавливайте ROS 2 на хост: используйте предоставленный преподавателем контейнер и сообщите о недостающей конфигурации.

## Шаг 2. Проверить контейнер и ROS 2

В новом терминале VS Code проверьте:

```bash
hostname
whoami
pwd
ros2 --help
```

Затем запустите demo publisher:

```bash
ros2 run demo_nodes_cpp talker
```

Ожидаемый результат: вывод строк `Publishing: 'Hello World: N'`. Остановите узел сочетанием `Ctrl+C`.

Опционально, во втором терминале контейнера запустите:

```bash
ros2 run demo_nodes_cpp listener
```

Ожидаемый результат: listener получает сообщения talker. После проверки завершите оба процесса через `Ctrl+C`.

## Шаг 3. Создать папку личной модели

```bash
mkdir -p ~/my_robot
cd ~/my_robot
```

Запишите краткое описание. Пример можно адаптировать под свою идею:

```bash
printf '# My robot\n\nКолёсная платформа с лидаром и RGB-камерой для автономного движения в помещении.\n' > README.md
```

В `README.md` укажите:

1. имя и назначение робота;
2. тип платформы (например, дифференциальная база);
3. два предполагаемых сенсора;
4. какую задачу робот должен будет выполнять.

## Шаг 4. Добавить `.gitignore` до первого коммита

```bash
printf 'build/\ninstall/\nlog/\n__pycache__/\n*.py[cod]\n.env\n*.key\n*.pem\nid_ed25519\n' > .gitignore
```

Каталоги `build/`, `install/`, `log/` будут появляться на следующих этапах курса при сборке ROS workspace. Файлы ключей и локальные секреты нельзя добавлять в Git.

Проверьте статус:

```bash
git status --short
```

Ожидаемый результат: `README.md` и `.gitignore` видны как новые файлы.

## Шаг 5. Сделать первый коммит

```bash
git init -b main
git config user.name "Ваше имя"
git config user.email "ваш@email"
git add README.md .gitignore
git diff --staged
git commit -m "Создал основу модели робота"
git status --short
git log --oneline -1
```

Замените имя и email на свои. Это локальные настройки данного репозитория. Не добавляйте секреты, пароли или токены.

Ожидаемый результат: `git status --short` пуст; `git log --oneline -1` показывает один коммит.

## Шаг 6. Проверить устойчивость файлов

Репозиторий `~/my_robot/` создан вне временного слоя контейнера, в домашней папке пользователя. Проверить путь и состояние можно командами:

```bash
pwd
git status --short
git log --oneline
```

Если Dev Container настроен с постоянной домашней директорией, данные остаются доступны при следующем подключении. Главное для курса — хранить проект внутри рабочей области, которая подключена к контейнеру, и регулярно фиксировать изменения в Git.

## Самопроверка

1. Где выполнялись команды `ros2 --help` и `talker` — на хосте или в контейнере?
2. Чем отличаются `git add` и `git commit`?
3. Какие папки будущей сборки исключает `.gitignore`?
4. Где будет следующий элемент робота — URDF, пакет или узел — и почему он попадёт в этот же репозиторий?

## Критерии выполнения

- Учебный проект открыт в Dev Container либо преподавателю сообщено, что конфигурация недоступна.
- `ros2 --help` показывает справку внутри контейнера.
- `talker` публикует `Hello World` и корректно останавливается.
- В `~/my_robot/README.md` описан робот, база, сенсоры и назначение.
- `.gitignore` исключает build outputs и локальные секреты.
- `git log --oneline -1` показывает первый коммит, а `git status --short` не показывает незакоммиченных файлов.
- ROS 2 не устанавливался на хост.

## Типичные ошибки

| Симптом | Причина | Исправление |
| --- | --- | --- |
| `ros2: command not found` | Команда выполнена на хосте или Dev Container не открыт | В VS Code выбрать Reopen in Container; ROS 2 на хост не ставить. |
| После правки Dockerfile среда старая | Контейнер не пересобран | Выполнить Rebuild Container. |
| Коммит пустой | Файлы не добавлены в индекс | `git status`, `git add README.md .gitignore`, `git diff --staged`. |
| `build/` появляется в status | `.gitignore` не создан или путь уже отслеживается | Проверить правило и `git check-ignore -v <путь>`. |
| Данные не видны после пересоздания контейнера | Проект создан вне постоянного workspace | Перенести `~/my_robot/` в подключённую рабочую область или настроить постоянное хранилище по инструкции курса. |

## Что сдавать

Передать преподавателю:

- содержимое `README.md` (без персональных секретов);
- содержимое `.gitignore`;
- вывод `git log --oneline -1`;
- одно предложение о проверке ROS 2 внутри контейнера.

Не прикладывайте токены, пароли, приватные ключи и файлы `.env`.
