# Домашнее задание 5: сенсоры своей модели робота

## Цель

Описать, какие датчики будут у собственной модели робота: какие данные и с какой частотой они дают и какому потребителю эти данные нужны.

## Связь с темой занятия

Занятие 5 показало путь «физическая величина → сенсор → данные → потребитель» и то, что виртуальный сенсор даёт те же типы данных, что и реальный. Дома студент применяет это к своей модели: выбирает сенсоры и фиксирует, что именно они измеряют.

## Предварительные требования

- Идея робота и папка `~/my_robot/` из [`hw_02_setup.md`](hw_02_setup.md).
- Набросок модели (платформа + колёса) из [`hw_04_robotcad.md`](hw_04_robotcad.md).
- Дневник `~/my_robot/diary.md` из [`hw_03_opencode.md`](hw_03_opencode.md).
- Статья [`../2_knowledge/sensors.md`](../2_knowledge/sensors.md).
- Выполняется дома в devcontainer (ROS2 Jazzy, уровень 2); ROS2 не устанавливается на хост.

## Шаг к виртуальной модели робота

Это первый шаг от «корпуса» к «восприятию»: к платформе с колёсами добавляется список сенсоров. Они станут источниками данных, которые в занятиях 6–9 превратятся в узлы, публикующие данные в темы. Сейчас важно зафиксировать, **что** робот будет измерять.

## Шаги

### Шаг 1. Выбрать набор сенсоров

Для мобильного робота разумный минимум:

- **LiDAR** — видеть препятствия и строить карту;
- **IMU** — чувствовать наклон и повороты;
- **энкодеры на колёсах** — знать, сколько проехали (одометрия);
- **RGB- или RGBD-камера** — видеть объекты.

Выберите свой набор (не обязательно все четыре) и обоснуйте каждый датчик одной фразой: зачем он нужен роботу.

### Шаг 2. Для каждого сенсора: данные и частота

Заполните таблицу в дневнике `~/my_robot/diary.md`:

```markdown
## Сенсоры моей модели

| Сенсор | Физическая величина | Данные | Частота |
| --- | --- | --- | --- |
| LiDAR | расстояние до препятствий | массив дальностей по углам | 10 Гц |
| IMU | ускорение и поворот | угловая скорость, линейное ускорение | 100 Гц |
| энкодер | угол поворота колеса | счётчик оборотов / скорость | 200 Гц |
| RGB-камера | изображение | кадр из пикселей | 30 кадров/с |
```

Частоту укажите свою и коротко объясните выбор: почему для IMU частота выше, чем для камеры.

### Шаг 3. Определить потребителя данных

Для каждого сенсора напишите, какой программе робота нужны его данные:

```markdown
- LiDAR → навигация (объезд препятствий, карта)
- IMU + энкодеры → оценка положения (одометрия)
- RGB-камера → распознавание объектов
```

Если потребителя ещё нет — напишите «потребитель появится позже», но укажите, для какой задачи.

### Шаг 4. Виртуальный или реальный

Отметьте, какой сенсор сначала будет виртуальным (в Gazebo) и почему:

```markdown
- На этапе обучения все сенсоры виртуальные (Gazebo) — данные те же, железо покупать не нужно.
- Позже перенесу на Raspberry Pi: LiDAR по USB, IMU и дальномеры по I2C.
```

## Ожидаемый результат

- В `~/my_robot/diary.md` есть раздел «Сенсоры моей модели».
- Для каждого сенсора указаны физическая величина, данные и частота.
- Для каждого сенсора указан потребитель (или будущая задача).
- Студент объясняет, почему выбранная частота подходит задаче.

## Вопросы для самопроверки

1. Почему IMU обычно опрашивают чаще, чем камеру?
2. Что изменится в программе-потребителе, если заменить реальный лидар на виртуальный?
3. Какому потребителю нужны данные энкодеров и зачем?
4. Как данные выбранных сенсоров попадут в ROS2? (подсказка: тема занятия 9)

## Критерии оценки

Задание выполнено, если:

- выбран и обоснован набор сенсоров (минимум 2);
- для каждого сенсора указаны данные и частота;
- для каждого сенсора указан потребитель данных;
- отмечено, какие сенсоры виртуальные, а какие позже станут реальными;
- записи занесены в `~/my_robot/diary.md`.

## Типичные ошибки

| Симптом | Причина | Исправление |
| --- | --- | --- |
| Частота не указана или «просто большая» | Не подумал, зачем частота нужна | Привязать частоту к задаче: кадр — 30, лидар — 10, IMU — сотни |
| Путают данные и физическую величину | В колонке «данные» написано «видит стены» | Писать конкретно: «массив дальностей», «кадр из пикселей» |
| Нет потребителя данных | Сенсор «для красоты» | Каждый сенсор должен кормить какую-то программу |
| Выбран сенсор без обоснования | Копия чужого списка | Одной фразой объяснить, зачем роботу этот датчик |
