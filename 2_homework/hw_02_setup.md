# Домашнее задание 2: настройка окружения дома и первый коммит

## Цель

Настроить на домашнем компьютере клон проекта, собрать контейнер уровня 2, проверить работу ROS2 и сделать первый коммит своей будущей модели робота.

## Связь с темой занятия

Занятие 2 объяснило, почему ROS2 не ставится на хост и как контейнер воспроизводит окружение, а Git хранит историю изменений. Дома студент применяет это на практике: настраивает ту же среду, что и в классе, и заводит историю для своей модели.

## Предварительные требования

- Дома установлены Git, VS Code и Docker (или резервный вариант виртуализации).
- Полная инструкция — в [`../2_knowledge/home_setup.md`](../2_knowledge/home_setup.md). ROS2 не устанавливается на хост.
- Понятия образа, контейнера, тома и Dev Container — [`../2_knowledge/docker_devcontainer.md`](../2_knowledge/docker_devcontainer.md).
- Основы Git — [`../2_knowledge/git.md`](../2_knowledge/git.md).

## Шаг к виртуальной модели робота

Модель робота ещё не строится (она начнётся с занятия 4). Здесь студент делает фундамент: заводит отдельный репозиторий для своей модели и фиксирует в нём первый коммит. Дальше каждое ДЗ будет добавлять в этот репозиторий новый элемент (пакет, узел, сенсор, навигацию), и история Git покажет весь путь.

## Шаги

### Шаг 1. Выбрать вариант установки

Откройте [`../2_knowledge/home_setup.md`](../2_knowledge/home_setup.md) и пройдите один из трёх вариантов под Windows:

- WSL2 — слой Linux внутри Windows, Docker Desktop поверх WSL2;
- Dev Container — рекомендуемый путь: Docker Desktop + расширение Dev Containers;
- VirtualBox — резервный, если виртуализация для Docker недоступна.

На macOS и Linux контейнер работает нативно — инструкция там же.

### Шаг 2. Склонировать проект

```bash
git clone <URL-репозитория> ROS2_basic_course_SESC
cd ROS2_basic_course_SESC
code .
```

Ожидаемый результат: папка проекта склонирована и открыта в VS Code.

### Шаг 3. Собрать контейнер уровня 2

В VS Code: Ctrl+Shift+P → «Dev Containers: Reopen in Container». При первой сборке скачивается образ и ставится окружение — дождитесь окончания.

### Шаг 4. Проверить ROS2

Внутри контейнера выполните:

```bash
ros2 --help
ros2 run demo_nodes_cpp talker
```

Ожидаемый результат: `ros2 --help` выводит справку по CLI; `talker` каждые 0.5 с печатает `[INFO] ... Publishing: 'Hello World: N'`. Остановите Ctrl+C.

### Шаг 5. Создать папку своей модели

```bash
mkdir -p ~/my_robot && cd ~/my_robot
printf '# My robot\n\nКолёсный робот с лидаром и рукой-манипулятором.\n' > README.md
```

Опишите идею робота коротко: сколько колёс, какие сенсоры, есть ли манипулятор.

### Шаг 6. Создать `.gitignore`

```bash
printf 'build/\ninstall/\nlog/\n__pycache__/\n*.pyc\n.env\n*.key\n*.pem\nid_ed25519\n' > .gitignore
```

`build/`, `install/`, `log/` появятся при сборке `colcon` (занятие 7), ключи и пароли в историю не попадают.

### Шаг 7. Первый коммит

```bash
git init -b main
git config user.name "Ваше имя"
git config user.email "ваш@email"
git add README.md .gitignore
git commit -m "Первый коммит: идея модели робота"
git log --oneline
```

Ожидаемый результат: в `git log --oneline` один коммит. Папка `~/my_robot/` — собственный репозиторий, отдельный от курса.

## Ожидаемый результат

- Проект склонирован, контейнер уровня 2 собран и открывается.
- `ros2 --help` и `ros2 run demo_nodes_cpp talker` работают внутри контейнера.
- В `~/my_robot/` есть репозиторий с `.gitignore`, `README.md` и первым коммитом.

## Вопросы для самопроверки

1. Почему ROS2 не ставится на хост, а живёт в контейнере?
2. Чем `git add` отличается от `git commit`?
3. Что попадает в `.gitignore` вашей модели и почему?
4. Что делать, если после изменения `devcontainer.json` окружение устарело?

## Критерии оценки

Задание выполнено, если:

- выбран и пройден один из вариантов установки из `home_setup.md`;
- `git clone` проекта выполнен, контейнер уровня 2 собран;
- `ros2 --help` и `ros2 run demo_nodes_cpp talker` дают ожидаемый вывод;
- создан репозиторий `~/my_robot/` с `.gitignore` и первым коммитом;
- студент отвечает на вопросы самопроверки.

## Типичные ошибки

| Симптом | Причина | Исправление |
| --- | --- | --- |
| Docker/WSL2 не стартует | Виртуализация выключена в BIOS | Включить VT-x/AMD-V в BIOS/UEFI |
| `ros2: command not found` внутри контейнера | Контейнер не собран или не активирован `setup.bash` | «Dev Containers: Rebuild Container» |
| Контейнер не пересобран | Правки конфигурации не применились | «Dev Containers: Rebuild Container» |
| Команды выполняются на хосте | Терминал открыт не в Dev Container | Переоткрыть проект в контейнере |
| Коммит пустой | Забыли `git add` | `git add` файлов перед `git commit` |
| `~/my_robot/` пропал после пересборки | Файлы созданы вне смонтированной папки | Хранить код в workspace или отправить на remote (`git push`) |
