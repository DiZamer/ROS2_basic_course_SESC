# Домашняя работа-v2 03: проверенный запрос к OpenCode

## Цель

Использовать OpenCode для чтения собственного описания робота, проверить утверждения по исходным файлам и записать результат в дневник проекта.

## Связь с занятием

На занятии студент увидел, что агент может искать и объяснять файлы, но может и ошибаться. Дома он тренирует безопасную петлю: запрос → источник → ручная проверка.

## Предварительные требования

- OpenCode установлен и доступен с настроенным провайдером.
- Существует личный репозиторий `~/my_robot/` из домашней работы занятия 2.
- В `~/my_robot/README.md` кратко описана идея робота.
- Доступен `opencode.jsonc` курса и статья [`opencode_agent.md`](../2_knowledge/opencode_agent.md).

Если OpenCode ещё не доступен, выполните текстовую часть с подготовленным преподавателем примером; не вводите секреты и не меняйте глобальные права системы.

## Шаг к виртуальной модели

Это задание пока не добавляет ROS-пакет. Оно создаёт дневник разработки, где будут зафиксированы будущие решения о базе, сенсорах, узлах и симуляции.

## Шаг 1. Проверить настройки

```bash
opencode --version
opencode --help
```

Откройте конфигурацию курса и запишите, как настроены `edit` и `bash`. Не вставляйте в дневник значения API-ключей и токенов.

## Шаг 2. Задать ограниченный вопрос

Перейдите в личную папку модели и запросите только анализ:

```bash
cd ~/my_robot
opencode run --agent plan "Прочитай только README.md. Сформулируй назначение робота и назови два факта, на которых основан ответ. Ничего не меняй и не запускай команды."
```

Перед подтверждением действий проверьте эффективные права выбранного агента. Не выполняйте запрос из Build с разрешённым редактированием.

## Шаг 3. Проверить факты

Откройте `README.md` и отметьте в черновике:

| Утверждение агента | Есть в README? | Что уточнить |
| --- | --- | --- |
| Назначение робота | Да/нет | … |
| Тип базы или сенсор | Да/нет | … |

Не записывайте как факт то, чего нет в исходном описании.

## Шаг 4. Добавить дневник

```bash
cd ~/my_robot
touch diary.md
```

В редакторе добавьте запись:

```markdown
# Дневник разработки

## Занятие 3 — проверка OpenCode
- Вопрос агенту: …
- Подтверждённый факт и файл-источник: …
- Неподтверждённое/неясное утверждение: …
- Проверил вручную: да/нет
```

## Ожидаемый результат

- Выполнен или разобран один ограниченный вопрос.
- В дневнике указан факт и путь к источнику.
- Отмечено хотя бы одно ограничение ответа или что требовало проверки.
- Проектные файлы не изменены неожиданно.

## Самопроверка

1. Почему `AGENTS.md` не является техническим запретом на команду shell?
2. Как ты проверил, что агент использовал нужный файл?
3. Какие permissions действовали для выбранного агента?
4. Какие данные нельзя включать в prompt?

## Критерии выполнения

- OpenCode/демонстрационный режим был доступен либо использован резервный пример.
- В дневнике есть вопрос, ответ, источник и ручная проверка.
- Нет секретов и токенов.
- Работа осталась в `~/my_robot/`, а не в репозитории курса.

## Типичные ошибки

| Ошибка | Исправление |
| --- | --- |
| Запрос слишком общий | Ограничить анализ одним файлом и форматом ответа. |
| Ответ переписан без проверки | Открыть источник и отметить подтверждение. |
| Агент просит запустить правку | Отменить действие; использовать тестовую папку и проверить права. |
| В дневник попал секрет | Удалить его из проекта и немедленно отозвать, если он был передан/опубликован. |
