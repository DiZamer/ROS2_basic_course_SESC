# Домашняя работа-v2 06: архитектура моей ROS 2-модели

## Цель

Описать собственную модель робота как несколько подсистем/узлов, связанных ROS 2-интерфейсами, и объяснить выбранный `ROS_DOMAIN_ID`.

## Связь с занятием

На занятии студент увидел, как ROS Graph отражает работающую систему и как домен разделяет графы. В этом задании он планирует архитектуру до написания узлов.

## Предварительные требования

- Есть `~/my_robot/README.md`.
- Доступен дневник проекта из предыдущих заданий.
- Используй Dev Container для ROS-команд; ROS 2 на хост не устанавливай.

## Шаг к модели

Это архитектурный план будущих компонентов, который станет основой для workspace, пакетов и узлов на занятиях 7–8.

## Шаг 1. Разбить задачу на узлы

Выбери минимум три узла для своего сценария. Например:

- `sensor_node` — выдаёт измерения;
- `state_estimator` — оценивает положение;
- `navigation_node` — формирует команды базы.

На этом шаге имена обозначают роли, код писать не нужно.

## Шаг 2. Нарисовать graph

В `~/my_robot/diary.md` добавь схему:

```text
sensor_node ── /sensor_data ──> state_estimator ── /pose ──> navigation_node
```

Подпиши для каждой стрелки: topic/service/action пока только как предположение, тип данных и направление.

## Шаг 3. Выбрать domain

Запиши одно значение в учебном диапазоне `0–101`:

- для изолированной разработки одного робота — собственный домен, не конфликтующий с соседними группами;
- для узлов, которым надо общаться, значение должно быть одинаковым.

Не меняй домен запущенного робота TIAGo. Выбор относится к твоей будущей модели.

## Шаг 4. Проверить понятность схемы

Для каждого узла ответь:

- что он получает;
- что выдаёт;
- кто использует выход;
- как проверить связь после запуска.

## Ожидаемый результат

- Минимум три узла;
- схема с направлениями потоков;
- интерфейс-кандидат и тип данных на каждой связи;
- выбранный domain ID и объяснение, когда участники должны совпадать.

## Вопросы для самопроверки

1. Почему ROS Graph — это не дерево исходных файлов?
2. Что обеспечивает автоматическое обнаружение узлов?
3. Зачем нескольким студентам на одном компьютере выбирать разные domain ID?
4. Какой слой находится между ROS API и конкретным middleware?

## Критерии выполнения

- Архитектура соответствует задаче робота.
- У каждой стрелки есть направление и назначение.
- Не смешаны понятия Node, DDS, RMW и domain.
- Все команды ROS относятся к контейнеру, ROS 2 не устанавливался на host.
