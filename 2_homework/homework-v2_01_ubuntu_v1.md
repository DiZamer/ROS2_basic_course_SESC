# Домашняя работа-v2 01: терминал и рабочие каталоги

> Выполняется в Dev Container курса. Цель — закрепить базовые команды до создания первого пакета ROS 2. ROS 2 на хост не устанавливается.

## Цель

Повторить навигацию и работу с файлами, проверить права и справку, подготовить рабочую папку будущего ROS workspace и объяснить безопасное обращение с SSH-ключами.

## Связь с занятием

На занятии студент разобрал команду, shell, файлы, права и SSH. Дома он тренируется проверять контекст перед командами и сохраняет первые заметки о собственной модели.

## Предварительные требования

- Учебный проект открыт в Dev Container уровня 2 (Ubuntu 24.04).
- Терминал VS Code подключён к контейнеру.
- Прочитаны [`lecture-v2_content_01_ubuntu_v1.md`](../1_lecture/lecture-v2_content_01_ubuntu_v1.md) и [`ubuntu_cli.md`](../2_knowledge/ubuntu_cli.md).
- ROS 2 не устанавливается на хост.

## Шаг к виртуальной модели

Создать и описать рабочий каталог `~/ros2_ws/src/`. В следующих занятиях в нём появятся ROS 2-пакеты и описание собственного робота. На этом задании полноценная модель ещё не создаётся.

## Шаг 1. Подтвердить контекст

В терминале Dev Container выполните:

```bash
pwd
whoami
cat /etc/os-release
```

Запишите текущую папку, пользователя и версию Ubuntu. Ожидается пользователь курса внутри Ubuntu 24.04.

## Шаг 2. Создать рабочую структуру

```bash
mkdir -p ~/ros2_ws/src
cd ~/ros2_ws
pwd
ls -la
ls -la src
```

Ожидаемый результат: существует `~/ros2_ws/src`, а текущий каталог — `~/ros2_ws`.

## Шаг 3. Создать краткую заметку о модели

```bash
printf '# Моя модель робота\n\nПлатформа: (например, дифференциальная база).\nЗадача: (что робот должен делать).\n' > ~/ros2_ws/robot_idea.md
```

Откройте файл редактором VS Code и замените подсказки своими словами. Не записывайте пароли, адреса приватных сетей и ключи.

## Шаг 4. Проверить файлы и права

```bash
ls -l ~/ros2_ws/robot_idea.md
cp ~/ros2_ws/robot_idea.md ~/ros2_ws/robot_idea_backup.md
mv ~/ros2_ws/robot_idea_backup.md ~/ros2_ws/robot_idea_copy.md
ls -la ~/ros2_ws
```

Ожидаемый результат: есть исходная заметка и её копия. Удалять оригинал не требуется.

## Шаг 5. Найти команды и прочитать помощь

```bash
command -v bash
printf '%s\n' "$PATH"
ls --help
help cd
```

Запишите одним предложением, чем встроенная команда `cd` отличается от программы `ls`.

## Шаг 6. Безопасно проверить SSH-ключи

Сначала только проверьте наличие SSH-каталога и ключевых файлов:

```bash
ls -la ~/.ssh
```

Если в рамках этого курса ключ ещё не создавался и преподаватель просил выполнить генерацию, создайте отдельный **учебный** ключ под новым именем:

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
key_path="$HOME/.ssh/course_lab_ed25519"
if [ -e "$key_path" ] || [ -e "$key_path.pub" ]; then
  printf 'Учебный ключ уже существует; не перезаписываю.\n'
else
  ssh-keygen -t ed25519 -N "" -f "$key_path"
fi
if [ -f "$key_path.pub" ]; then
  ssh-keygen -lf "$key_path.pub"
fi
```

Если файл уже существует, не перезаписывайте его: выберите новое имя для учебной пары. Приватный ключ `course_lab_ed25519` нельзя отправлять преподавателю или коммитить; сдаётся только объяснение назначения публичного ключа. Если домашний каталог контейнера не сохраняется, не полагайтесь на него как на место хранения личного ключа.

## Ожидаемый результат

- Создан `~/ros2_ws/src/`.
- В `~/ros2_ws/robot_idea.md` описаны тип платформы и задача робота.
- Студент умеет проверять путь, пользователя и права файла.
- Студент объясняет назначение `PATH` и не путает публичный/приватный ключ.

## Вопросы для самопроверки

1. Почему `pwd` стоит проверить перед относительным путём?
2. Как узнать, где находится команда `bash`?
3. В чём разница между `chmod` и `sudo`?
4. Почему приватный SSH-ключ нельзя включать в репозиторий?

## Критерии оценки

- Команды выполняются внутри Dev Container.
- Создана папка workspace и заметка о роботе.
- `command -v bash` и `ls --help` работают.
- Студент может объяснить минимум три команды по схеме «что меняет → как проверить».
- Секреты и приватные ключи не передавались и не коммитились.

## Типичные ошибки

| Ошибка | Исправление |
| --- | --- |
| Работают не в том терминале | В VS Code проверить признак Dev Container и выполнить `hostname`. |
| Перезаписали существующий ключ | Остановиться; всегда выбирать уникальное имя `course_lab_ed25519`. |
| Создали заметку в `/tmp` | Переместить её в `~/ros2_ws`, где расположена рабочая папка. |
| Используют `sudo` для обычных файлов | Работать от пользователя контейнера; `sudo` оставить системным операциям. |

## Что сдавать

- Текст `robot_idea.md`.
- Вывод `pwd`, `whoami` и `ls -la ~/ros2_ws`.
- Короткое объяснение разницы публичного и приватного SSH-ключа.

Не прикладывайте содержимое приватного ключа.
