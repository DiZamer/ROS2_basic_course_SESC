# Домашнее задание 1: Ubuntu и командная строка

## Цель

Настроить терминал дома, повторить базовые команды Linux, создать пару SSH-ключей и убедиться, что окружение готово к следующим занятиям.

## Связь с темой занятия

Занятие 1 дало базу: навигация по файловой системе, права, `apt`, справка и SSH. Дома студент закрепляет эти навыки на своём компьютере и готовит окружение, в котором дальше строится виртуальная модель робота.

## Предварительные требования

- Клонирован проект курса (см. [`../2_knowledge/home_setup.md`](../2_knowledge/home_setup.md)).
- Открыт Dev Container уровня 2 (`.devcontainer/`, Ubuntu 24.04 + ROS2 Jazzy).
- ROS2 не устанавливается на хост — все команды выполняются внутри контейнера.

## Шаг к виртуальной модели робота

Это задание — фундамент, а не элемент модели. Студент готовит среду и привычку работать в терминале; с занятия 2 (`hw_02_setup.md`) начнётся сборка окружения, а с занятия 4 — сама модель робота.

## Шаги

### Шаг 1. Проверить версию оболочки

```bash
bash --version
```

Ожидаемый результат: строка вида `GNU bash, version 5.2.x`. Если команда не найдена — оболочка недоступна, повторите настройку контейнера.

### Шаг 2. Повторить команды навигации и файлов

Выполните последовательность и зафиксируйте результат:

```bash
pwd
whoami
cat /etc/os-release
mkdir -p ~/ros2_ws/src
ls ~/ros2_ws
touch ~/ros2_ws/src/.gitkeep
ls -la ~/ros2_ws/src
```

Ожидаемый результат: `pwd` → `/home/ubuntu`, `whoami` → `ubuntu`, `cat /etc/os-release` → `Ubuntu 24.04`, в `~/ros2_ws/src/` виден файл `.gitkeep`.

### Шаг 3. Настроить права и потренировать sudo

```bash
cd ~/ros2_ws/src
echo "hello robot" > hello.txt
chmod +x hello.txt
ls -l hello.txt
sudo apt update
```

Ожидаемый результат: у `hello.txt` стоит право `x`, `sudo apt update` обновляет список пакетов без ошибок.

### Шаг 4. Прочитать справку

```bash
ls --help
man ls    # выход — q
```

Ожидаемый результат: вы можете объяснить, что делают опции `-l` и `-a`.

### Шаг 5. Создать SSH-ключ

```bash
ssh-keygen -t ed25519 -C "student@home" -f ~/.ssh/id_ed25519
```

Ожидаемый результат: в `~/.ssh/` появились `id_ed25519` (приватный) и `id_ed25519.pub` (публичный). Приватный ключ не показывайте никому и не загружайте в репозиторий.

### Шаг 6. Проверить стандартные потоки

```bash
echo "first" > ~/ros2_ws/src/log.txt
echo "second" >> ~/ros2_ws/src/log.txt
cat ~/ros2_ws/src/log.txt
cat ~/ros2_ws/src/log.txt | grep second
```

Ожидаемый результат: `cat` выводит две строки; `grep second` — только строку `second`.

## Ожидаемый результат

- `bash --version` показывает версию оболочки.
- Студент свободно создаёт папки и файлы, меняет права и читает справку.
- Создан SSH-ключ, который пригодится для подключения к Raspberry Pi робота (этап 3, занятия 25–30).
- Workspace `~/ros2_ws/src/` готов к созданию первого пакета.

## Вопросы для самопроверки

1. Что выводит `pwd` и зачем он нужен?
2. Чем `>` отличается от `>>`?
3. Где хранится приватный SSH-ключ и почему его нельзя никому передавать?
4. Почему для `apt install` нужен `sudo`, а для `ls` — нет?

## Критерии оценки

Задание выполнено, если:

- `bash --version` показывает версию 5.x;
- создана папка `~/ros2_ws/src/` с файлом `.gitkeep`;
- `sudo apt update` завершается без ошибок;
- в `~/.ssh/` есть пара ключей `id_ed25519` / `id_ed25519.pub`;
- студент отвечает на вопросы самопроверки.

## Типичные ошибки

| Симптом | Причина | Исправление |
| --- | --- | --- |
| `bash: ssh-keygen: command not found` | Не установлен `openssh-client` | `sudo apt install -y openssh-client` |
| `Permission denied` при подключении к роботу | Публичный ключ не скопирован на робота | `ssh-copy-id user@host` или вручную в `~/.ssh/authorized_keys` |
| `rm` удалил нужный файл | Путь указан неверно | Проверяйте `pwd` и путь перед `rm` |
| Команда выполняется на хосте, а не в контейнере | Терминал открыт не в Dev Container | Переоткрыть проект в контейнере |
