# Курс «Основы продвинутой робототехники»

Образовательный комплект для годового курса по ROS2 для студентов магистратуры физико-технического университета.

Курс длится два семестра и состоит из 30 занятий по 120 минут. Каждое занятие устроено одинаково: 40 минут лекции (уровень 1), 40 минут практики (уровень 2) и 40 минут практики по кейсу робота (уровень 3). После каждого занятия студент получает домашнее задание, которое шаг за шагом ведет его к собственной виртуальной модели робота.

**Главная цель**: к концу курса студент перестает бояться ROS2, самостоятельно разрабатывает распределенное робототехническое приложение, доводит домашние задания до собственной виртуальной модели робота и работает с реальными роботами.

Курс дает ROS2 как общий инженерный язык робототехники для сенсорики, цифровых двойников, YOLO, SLAM, Nav2, VLA, манипуляторов, sim-to-real, M2M и информационной безопасности.

## Как устроен курс

Материал организован в три уровня. Все три уровня проходятся на одном занятии за 120 минут (40+40+40).

| Уровень | Место в занятии | Где находится | Роль |
| --- | --- | --- | --- |
| **1. Лекция** | первые 40 минут | `1_lecture/`, `1_slides/`, `1_demo/` | Объяснить концепции, показать схемы и фрагменты кода, дать маршрут дальше. |
| **2. Практика** | следующие 40 минут + домашнее задание | `2_knowledge/`, `2_practice/`, `2_code/`, `2_cheatsheets/`, `2_homework/`, `.devcontainer/` | Дать готовые инструкции и минимальный код по принципу «сделай так и заработает» в контейнерной среде, закрепить дома через ДЗ. |
| **3. Кейс робота** | последние 40 минут | `3_Robot/TIAgo_humble/` | Показать, как те же механизмы собираются в архитектуру мобильного манипулятора TIAGo. Это не только демонстрация: где применимо, уровень 3 дополнен «смелыми тестами» — экспериментами с конкретными командами на TIAgo (цель, команды, ожидаемый результат, возможный сбой и возврат в норму). |

Каждая тема занятия содержит три ссылки:

- **Уровень 2** — подробный материал, практику или код для самостоятельного повторения;
- **Уровень 3** — где эта технология используется в архитектуре робота из `3_Robot/`;
- **Домашнее задание** — как тема продолжается в `2_homework/` и какой шаг к собственной виртуальной модели робота делает студент.

Финальный этап курса (занятия 25–30) проходит на реальных роботах из `3_Robot/MentorPi_M1/` (ровер с лидаром, RGBD-камерой и omni-колёсами на Raspberry Pi с ROS2) и `3_Robot/MaxArm/` (манипулятор с вакуумным захватом, камерой распознавания, вентилятором и рельсой на ESP32).

## Среда выполнения

**ROS2 не устанавливается на хост.** Все работает в контейнерах.

Занятия проходят в компьютерном классе: у студента есть клон проекта и готовые контейнеры. Дома у студента `git clone` проекта и тот же devcontainer.

| Среда | Контейнер | Состав |
| --- | --- | --- |
| **Уровень 2** | общий Dev Container в `.devcontainer/` | ROS2 Jazzy, Ubuntu 24.04, `colcon`, примеры кода из `2_code/`, Gazebo/Ignition для тем, где нужна симуляция |
| **Уровень 3** | контейнер `3_Robot/TIAgo_humble/` | ROS2 Humble, Ubuntu 22.04, Gazebo Classic 11, Nav2, MoveIt2, workspace робота |

Домашние задания выполняются дома в devcontainer: ROS2 Jazzy для заданий уровня 2 и TIAGo в ROS2 Humble для заданий уровня 3.

## Работа с GUI

Контейнер выводит графику через **виртуальный дисплей (Xvfb + VNC/noVNC)** — окна видны в браузере, X11-сервер на хосте не нужен. По умолчанию активен **Вариант 1 (VNC/браузер)**, работающий на любой ОС.

**Пример: два экрана (`rviz2` + `turtlesim`):**

```bash
# Терминал 1 (в контейнере): поднять два экрана
start_gui.sh --displays 2

# Терминал 2: RViz2 на экране 0
DISPLAY=:99  rviz2

# Терминал 3: turtlesim на экране 1
DISPLAY=:100 ros2 run turtlesim turtlesim_node

# Браузер на хосте:
#   вкладка 1 → http://localhost:6080 (RViz2)
#   вкладка 2 → http://localhost:6081 (turtlesim)
```

Все варианты запуска (один/несколько экранов, Gazebo, 5 вариантов вывода GUI, переключение на GPU, шпаргалки) — [`start_options_and_GUI.md`](start_options_and_GUI.md). Детали по TIAGo (уровень 3) — в [`3_Robot/TIAgo_humble/README.md`](3_Robot/TIAgo_humble/README.md).

## Свои пакеты и пересборка

Создавайте свои ROS2-пакеты **внутри `2_code/`** (или `2_homework/`). При создании или пересборке контейнера они собираются автоматически (`colcon build`) и подключаются к окружению (`source install/setup.bash`), поэтому сразу видны командам `ros2`.

```bash
# Создать свой пакет
cd 2_code
ros2 pkg create --build-type ament_python my_pkg
# Пересобрать после правок
colcon build
```

Для **запуска** достаточно `ros2 launch <pkg> <file>.launch.py` — overlay подключается автоматически при создании контейнера.

`ros2 pkg prefix my_pkg` — **необязательная диагностика**: печатает путь к пакету, если он виден; сообщает `Package '...' not found`, если overlay не подключён. Для обычной работы эта команда не нужна.

**Что переживает `Rebuild Container`:**
- файлы и пакеты в смонтированной рабочей папке (`/workspaces/...`) — сохраняются;
- изменения **вне** рабочей папки (например, в `/opt/ros`, `/usr`) — **не** сохраняются; Rebuild возвращает образ к исходному состоянию.

`colcon build` в `postCreateCommand` (скрипт `.devcontainer/post_create.sh`) выполняется при создании/пересборке контейнера, а не при каждом открытии.

### Типичные ошибки

| Ошибка | Причина | Исправление |
| --- | --- | --- |
| `Package '...' not found` | Overlay не подключён (старый контейнер) | **Rebuild Container**; диагностика: `ros2 pkg prefix gazebo_demo` |
| `Package '...' not found` после переименования папки проекта | Абсолютные пути в `build/install` устарели | `cd 2_code && rm -rf build install log && colcon build` |
| Пакет не найден после правок | Пакет не пересобран | `cd 2_code && colcon build`, затем новый терминал |
| `ros2: command not found` | Контейнер не активен | Открыть проект в Dev Container |

## Маршрут студента на 2 семестра

**Семестр 1 (занятия 1–12).** Окружение и инструменты (занятия 1–5): Ubuntu и командная строка, Docker и Dev Container, агентная инженерия с opencode, проект робота и URDF в RobotCAD, датчики. Затем архитектура ROS2 и базовые механизмы коммуникации (занятия 6–11): ROS Graph, middleware, workspace, package, node, topic, service, action. Завершается зачётом с оценкой (занятие 12).

**Семестр 2 (занятия 13–24).** Собственные интерфейсы, параметры и launch, tf2, QoS и lifecycle, симуляция (URDF/Xacro, Gazebo, `ros2_control`), навигация (Nav2), манипуляция (MoveIt2), восприятие и поведение (YOLO и LLM bridge) и мини-проект. Завершается зачётом с оценкой и демонстрацией собственной виртуальной модели робота (занятие 24).

**Этап 3 (занятия 25–30).** Работа с реальными роботами: ровером MentorPi M1 и манипулятором MaxArm.

## Целевая аудитория

Студенты магистратуры по робототехнике, мехатронике, автономным мобильным роботам и интеллектуальным робототехническим системам.

**Предполагается, что студент знает**: C++, Python (базово), Linux, устройство компьютера, основы робототехники.

**Не предполагается**, что студент знает ROS2, DDS, middleware, ROS Graph, Executor, QoS, tf2, launch, colcon или устройство ROS2 workspace.

## Главные принципы курса

- Практика важнее теории
- Каждый термин объясняется при первом использовании
- Сложная концепция сначала через аналогию, затем технически
- Каждая тема завершается практическим результатом
- Каждое занятие завершается домашним заданием в `2_homework/`
- Код и команды работают при копировании без изменений
- Все нетривиальные утверждения имеют ссылку на источник
