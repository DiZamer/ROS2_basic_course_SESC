# Занятие 1 — план lecture-v2: Ubuntu и командная строка

> Содержание: [`lecture-v2_content_01_ubuntu_v1.md`](lecture-v2_content_01_ubuntu_v1.md). Слайды: [`../1_slides/lecture-v2_slides_01_ubuntu_v1.md`](../1_slides/lecture-v2_slides_01_ubuntu_v1.md).

## Цель

Студент выполняет базовые операции в терминале, понимает безопасную границу `sudo` и объясняет, как SSH связывает клиент с удалённым роботом.

### Проверяемые результаты

- студент без подсказки использует `pwd`, `ls`, `cd`, `mkdir`;
- создаёт и запускает временный shell-скрипт;
- объясняет, что делает `PATH`, где смотреть помощь и как отличить stderr;
- различает публичный и приватный SSH-ключ;
- работает в терминале контейнера и показывает, что ROS 2 на хост не нужен.

## Подготовка преподавателя

- Открыть общий Dev Container уровня 2 (Ubuntu 24.04 + ROS 2 Jazzy); проверить `hostname`, `whoami`, `pwd`.
- Подготовить чистый временный каталог для демонстрации и отдельную пару SSH-ключей в `/tmp`, не использовать личную `.ssh`.
- Если запланирован живой SSH-сеанс, проверить одно из двух: доступный учебный SSH-хост или подготовленный disposable-контейнер с `openssh-server`.
- Для уровня 3 заранее открыть готовый контейнер TIAGo Humble и его README. Первый запуск не выполнять на занятии.
- Подготовить план Б через локальные листинги/снимки; не предполагать наличие Raspberry Pi в аудитории.

## Уровень 1 — лекция, 0–40 минут

| Минуты | Блок | Объяснить и показать | Проверка понимания |
| --- | --- | --- | --- |
| 0–4 | Вступление | Робот — компьютер; GUI не всегда доступен, поэтому пригодится CLI. | «Как открыть лог, если на роботе нет рабочего стола?» |
| 4–11 | Shell и команда | Терминал → shell → `PATH` → программа → stdout/stderr. | Разобрать `ls -la /tmp` на программу, опции и аргумент. |
| 11–19 | Файлы и навигация | Корень `/`, `~`, абсолютный и относительный пути, `pwd`, `ls`, `cd`, `mkdir`. | Предсказать текущую папку после двух `cd`. |
| 19–25 | Файлы и права | Создать скрипт, `chmod u+x`, запустить; объяснить владелец/группа/остальные. | Чем `x` на файле отличается от `x` на каталоге? |
| 25–30 | Программы и справка | `command -v`, `--help`, `man`; `apt`/`sudo` только в контейнере. | Когда команда нужна, но shell её не находит? |
| 30–37 | SSH | Клиент, сервер, host/port/user, ключевая пара; `scp`. | Что можно передавать на робота — public или private key? |
| 37–40 | Выходной вопрос | Прочитать `Permission denied` и `Connection refused`. | Студент называет два разных первых диагностических шага. |

### Демонстрационные команды

```bash
pwd
whoami
printf '#!/usr/bin/env bash\nprintf "hello robot\\n"\n' > /tmp/hello_robot.sh
chmod u+x /tmp/hello_robot.sh
/tmp/hello_robot.sh
command -v bash
help cd
```

**Переход:** «Теперь выполняем команды не наугад: сначала проверяем, где находимся и от чьего имени работаем».

## Уровень 3 — кейс TIAGo, 80–120 минут

Все команды выполняются в уже готовом контейнере TIAGo Humble.

| Время | Шаг | Команды / действие | Ожидаемый результат |
| --- | --- | --- | --- |
| 80–85 | Найти контекст | `whoami`, `pwd`, `cat /etc/os-release` | Понятны пользователь, каталог и Ubuntu контейнера. |
| 85–95 | Найти ROS 2 | `ls /opt/ros`, `ls /opt/ros/humble`, `ros2 --help` | Студент видит инструменты Humble в контейнере. |
| 95–105 | Найти workspace | `ls ~/ros2_ws`, `ls ~/ros2_ws/src` (если импортирован) | Workspace отделён от установки ROS. |
| 105–113 | Удалённая машина | Разобрать схему ноутбук → SSH → Raspberry Pi; подключаться только к учебному хосту с разрешением. | Понимает, что SSH-сеанс — другой computer, а не локальная папка. |
| 113–120 | Сверить и обобщить | Найти в README команду запуска TIAGo; отметить, где её выполнять. | Отличает host-команды Docker от команд ROS внутри контейнера. |

Не устанавливать SSH-сервер, не менять системные файлы и не выполнять команды, меняющие настоящий робот без разрешения инструктора.

## План Б

- Нет SSH-хоста: анализировать заранее подготовленный вывод `ssh -v` и различать DNS/порт/аутентификацию; не имитировать результат как настоящее сетевое подключение.
- TIAGo не запущен: показать README, `/opt/ros/humble` на снимке и структуру workspace.
- `man` отсутствует: использовать встроенную `help` для shell-команд и `команда --help` для внешних.
- `apt` недоступен: не терять время на сетевую настройку; объяснить роль пакетного менеджера на готовом выводе.
