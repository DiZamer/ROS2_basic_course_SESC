## Зачем это нужно в робототехнике

Мобильный робот — компьютер, которым часто управляют удалённо. Командная строка нужна, чтобы открыть каталог проекта, запустить узел, просмотреть лог или подключиться к компьютеру робота. ROS 2 на хосте курса не устанавливается: терминальные упражнения проходят в контейнере.

## Модель 1. Как команда превращается в действие

```text
Пользователь вводит строку
        ↓
Терминал показывает приглашение и вывод
        ↓
Shell (например, bash) разбирает команду
        ↓
Программа ищется по PATH и запускается с аргументами
        ↓
Результат → stdout; сообщения об ошибках → stderr
```

- **Терминал** — окно ввода и вывода текста.
- **Shell** — программа, которая разбирает команду и запускает другие программы.
- **Команда** обычно состоит из имени программы, опций и аргументов. В `ls -la /tmp` программа — `ls`, опции — `-la`, аргумент — `/tmp`.
- **PATH** — переменная окружения со списком каталогов, где shell ищет программы.

### Первые команды

```bash
pwd                 # текущий каталог
whoami              # текущий пользователь
ls -la              # файлы, включая скрытые
cd ~/ros2_ws        # перейти в каталог
mkdir -p ~/ros2_ws/src
```

`pwd` только сообщает место; `cd` меняет текущий каталог; `ls` показывает его содержимое.

## Модель 2. Файлы, пользователи и права

```text
/                         корень дерева файловой системы
├── home/ubuntu            домашний каталог пользователя
├── etc/                  системные настройки
├── usr/bin/              программы
├── opt/ros/humble/       ROS 2 в контейнере TIAGo
└── tmp/                  временные файлы
```

Права в `ls -l` показываются для владельца, группы и остальных пользователей. `r` означает чтение, `w` — запись, `x` — выполнение/проход по каталогу.

`sudo` запускает одну команду с повышенными правами. Используй его только там, где это нужно, и только внутри учебного контейнера. Не запускай весь терминал под `root`.

```bash
printf '#!/usr/bin/env bash\nprintf "hello robot\\n"\n' > ~/hello_robot.sh
chmod u+x ~/hello_robot.sh
~/hello_robot.sh
```

Ожидаемый результат: скрипт выводит `hello robot`. Флаг `x` сам по себе не добавляет программе возможностей; он разрешает её запуск.

## Модель 3. SSH — удалённая командная строка

**SSH** (Secure Shell) открывает защищённый терминальный сеанс на другой машине. Компьютер-оператор запускает SSH-клиент; целевая машина запускает SSH-сервер.

```text
Клиент: ноутбук / терминал контейнера
          │ ssh user@host
          ▼
Сервер: компьютер или Raspberry Pi робота
```

- Имя пользователя и адрес определяют целевую машину: `ssh user@host`.
- Порт SSH обычно 22; другой порт задают через `ssh -p PORT user@host`.
- **Публичный ключ** можно добавить на целевую машину.
- **Приватный ключ** хранится у владельца и не отправляется адресату.
- `scp` копирует файлы через SSH.

Публичный ключ не является паролем. Он позволяет серверу проверить подпись, созданную соответствующим приватным ключом.

Пример передачи файла, когда адрес и учётная запись предоставлены преподавателем:

```bash
scp config.yaml student@robot-host:~/config.yaml
```

`robot-host` здесь заменяется на настоящий адрес учебного сервера; команда не выполняется на неподготовленном адресе.

## Путь диагностики: наблюдай до изменения

| Симптом | Что проверить сначала | Типичная причина |
| --- | --- | --- |
| `command not found` | `command -v имя`, `echo "$PATH"` | Программа не установлена или её каталог не в `PATH`. |
| `Permission denied` при SSH | Имя пользователя, права домашнего каталога, публичный ключ и серверные логи | Ключ не добавлен или права/учётная запись неверны. |
| `Connection refused` | Адрес, порт, доступность SSH-сервера | Сервер не запущен или порт неверный. |
| Удалён не тот файл | `pwd`, затем `ls -la путь` | Путь указан не в том каталоге; `rm` не имеет корзины. |

`Permission denied` не всегда означает именно «не установлен ключ», а `Connection refused` отличается от сетевого тайм-аута: проверяй адрес, порт и сообщение целиком.

## Границы занятия

- Не устанавливать ROS 2 на хост.
- Не редактировать `/etc` и другие системные файлы.
- Не использовать реальные пароли и личные SSH-ключи на проекторе.
- `apt` и `sudo` демонстрировать внутри подготовленного контейнера; если пакет не нужен для учебной цели, использовать команды, уже доступные в образе.
- Установка OpenSSH-сервера выполняется только в disposable-контейнере и только при необходимости локального SSH-теста.

## Типичные ошибки

| Ошибка | Объяснение | Проверка |
| --- | --- | --- |
| Путают `cd` и `ls` | Одна команда меняет каталог, другая показывает содержимое | `pwd` до и после `cd`. |
| Применяют `sudo` к `cd` | `cd` встроен в shell и меняет каталог текущего процесса | Выполнить `cd` без `sudo`. |
| Думают, что `PATH` — список файлов | Это список каталогов для поиска программ | `printf '%s\n' "$PATH"`. |
| Показывают приватный ключ | Ключ даёт доступ от имени владельца | Никогда не выводить файл `id_*` в общий терминал. |
| Принимают любой SSH-отказ за ошибку ключа | Сеть, порт и аутентификация — разные этапы | Сверить точный текст ошибки и адрес/порт. |
