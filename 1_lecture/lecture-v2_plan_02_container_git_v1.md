> Четвёртый вариант: ясная подача из варианта 1 + четыре визуальные модели жизненного цикла из варианта 2. Содержание: [`lecture-v2_content_02_container_git_v1.md`](lecture-v2_content_02_container_git_v1.md). Marp: [`../1_slides/lecture-v2_slides_02_container_git_v1.md`](../1_slides/lecture-v2_slides_02_container_git_v1.md).

## Цель и результаты

Студент объясняет, чем образ отличается от контейнера, где хранится проект, как изменение проходит через Git и когда пересобирать Dev Container. Он создаёт проверенный коммит, ветку и `.gitignore`, затем находит те же идеи в среде TIAGo.

К концу занятия у студента есть:

- **уровень 2:** тестовый репозиторий, два коммита в `main`, ветка `feature/sensor`, чистая рабочая копия;
- **уровень 3:** объяснение, как конфигурация TIAGo подготавливает отдельное окружение;
- **после занятия:** личный `~/my_robot/` с первым коммитом и `.gitignore`.

## Подготовка преподавателя

- Открыть проект в подготовленном общем Dev Container уровня 2 (ROS 2 Jazzy). Проверить `hostname`, `whoami`, `ros2 --help`.
- Подготовить terminal на хосте для `docker ps`. Не предполагать, что Docker CLI/daemon доступны изнутри контейнера.
- Открыть презентацию [`../1_slides/lecture-v2_slides_02_container_git_v1.md`](../1_slides/lecture-v2_slides_02_container_git_v1.md).
- Для уровня 3 открыть README TIAGo, Dockerfile, `devcontainer.json`, `post_create.sh`, `post_start.sh`, `ros2_ws/tiago.repos` и `.gitignore`.
- Не запускать первую полную сборку TIAGo во время занятия: подготовка workspace может занять заметное время.

## Уровень 1 — лекция, 0–40 минут

| Минуты | Блок | Что объяснить / показать | Проверка понимания |
| --- | --- | --- | --- |
| 0–4 | Проблема «у меня работает» | Один исходный проект может запускаться по-разному из-за версий ОС и библиотек. | «Одинаковый commit гарантирует одинаковую сборку?» — нет. |
| 4–10 | Docker-модель | Схема Dockerfile → image → container. Образ — шаблон, container — запущенный экземпляр. | Попросить студента назвать, где выполняется ROS-команда. |
| 10–15 | Container и host | Контейнер изолирует процессы/файловое окружение, но использует ядро host; это не полноценная VM. | «Контейнер и виртуальная машина — одно и то же?» |
| 15–20 | Жизненный цикл файлов | На одной схеме показать папку проекта и bind mount, отдельно volume и writable layer. | «Где создать пакет, чтобы он оставался в проекте?» |
| 20–25 | Dev Container | Путь: открыть → подключить workspace → работать; Reopen vs Rebuild. | «Изменился Python-файл — нужен rebuild? Изменился Dockerfile?» |
| 25–33 | Git-цикл | Схема working tree → index → commit. Показать `status`, `diff`, `diff --staged`, `add`, `commit`, `log`. | «Что точно войдёт в commit?» — staged-содержимое. |
| 33–37 | Ветки и ignore | Ветка для эксперимента; `.gitignore` для новых build outputs и локальных секретов. | «Что делать, если секрет уже отправлен?» — отозвать/заменить. |
| 37–40 | Итог | Четыре быстрых диагностических ситуации. | Студент сначала называет команду наблюдения, затем действие. |

### Ключевые реплики

- «Образ — подготовленный шаблон, контейнер — его запущенный экземпляр».
- «Проект храните в workspace; не рассчитывайте на временный слой контейнера».
- «`git add` выбирает, `git commit` фиксирует».
- «Сначала проверьте состояние файла, потом решайте, добавлять или отменять».
- «Контейнер помогает выровнять среду, Git — проследить историю проекта».

### Мини-демонстрация Git

Команды показываются на отдельном временном репозитории, не на checkout курса:

```bash
git status --short
git diff
git add README.md
git diff --staged
git commit -m "Добавил идею робота"
git log --oneline -1
```

Ожидаемый вывод: после commit выбранная правка записана, а `git status --short` пуст.

## Уровень 2 — практика, 40–80 минут

Практическая инструкция: [`../2_practice/practice-v2_02_container_git_v1.md`](../2_practice/practice-v2_02_container_git_v1.md).

| Время | Действие | Контрольная точка |
| --- | --- | --- |
| 40–45 | Убедиться, что студент в Dev Container: `hostname`, `whoami`, `pwd`, `ros2 --help`. | Команды выполняются в среде уровня 2. |
| 45–50 | В отдельном host terminal выполнить `docker ps`. | Показано, что Docker управляется с хоста, если daemon не проброшен в контейнер. |
| 50–60 | Создать `~/git_practice`, инициализировать `main`, настроить автора, создать README и сделать первый commit. | Первый коммит виден через `git log --oneline`. |
| 60–67 | Создать `build/`, `install/`, `log/`; добавить `.gitignore`. | Неотслеживаемые артефакты исчезли из `git status`; объяснено ограничение ignore. |
| 67–75 | Создать `feature/sensor`, сделать commit правки README, вернуться в `main`. | На `main` feature-коммита нет до слияния. |
| 75–80 | Проверить `status`, ветки и историю; выполнить exit ticket. | Рабочая копия чистая, студент объясняет состояния Git. |

**Правило безопасности упражнения:** перед `git restore` посмотреть `git status` и `git diff`. Все потенциально отменяемые изменения выполняются в `~/git_practice`, а не в файлах курса.

## Уровень 3 — кейс TIAGo, 80–120 минут

Кейс основан на [`../3_Robot/TIAgo_humble/README.md`](../3_Robot/TIAgo_humble/README.md). Задача — прочитать существующую архитектуру, а не менять её.

| Время | Действие | Что студенты находят |
| --- | --- | --- |
| 80–85 | Сравнить уровни 2 и 3 | Общий контейнер курса — Jazzy; TIAGo — отдельная среда Humble. |
| 85–95 | Прочитать Dockerfile и `devcontainer.json` | Базовый образ и настройки запуска контейнера. |
| 95–105 | Сопоставить `post_create.sh` и `post_start.sh` | Различаются начальная подготовка и действия при старте. |
| 105–113 | Найти `tiago.repos` и `.gitignore` | Внешние исходники импортируются; результаты сборки не являются исходниками. |
| 113–118 | Если симуляция уже запущена — выполнить `pwd`, `ros2 node list`; иначе проследить README. | Связаны workspace и выполняющиеся ROS-процессы. |
| 118–120 | Сформулировать вывод | Один участник объясняет цепочку «конфигурация → container → источники → сборка». |

Не запускать `pkill`, удаление workspace, повторный `vcs import` или полную сборку. Для этого занятия достаточно безопасного чтения конфигурации.

## План Б

- **Нет доступа к Docker daemon:** показать контейнерный цикл на схеме; практику Git выполнить в контейнере.
- **Общий Dev Container не готов:** использовать предоставленную среду курса; ROS 2 на host не устанавливать ради занятия.
- **TIAGo не запущен:** разобрать README, Dockerfile, hooks, `.repos` и `.gitignore` как архитектурный кейс.
- **Мало времени:** сократить просмотр запущенных узлов, но сохранить Git-практику и сравнение уровней 2/3.
