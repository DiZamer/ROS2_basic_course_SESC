# Занятие 6 — план lecture-v2: архитектура ROS 2

Содержание: [`lecture-v2_content_06_ros_architecture_v1.md`](lecture-v2_content_06_ros_architecture_v1.md). Слайды: [`../1_slides/lecture-v2_slides_06_ros_architecture_v1.md`](../1_slides/lecture-v2_slides_06_ros_architecture_v1.md).

## Цель занятия

Студент связывает отдельные программы робота в ROS Graph и прослеживает путь данных от ROS API к middleware и обратно.

## Подготовка

- Общий Dev Container Jazzy готов; `demo_nodes_cpp` и `demo_nodes_py` доступны.
- Проверить GUI для `rqt_graph`; подготовить текстовый план Б.
- Закрыть лишние ROS-сессии и остановить ранее созданные ROS daemons в учебном контейнере.
- Для уровня 3 открыть TIAGo architecture docs и конфигурацию middleware; симуляцию во время этой практики не ломать.

## Тайминг 40+40+40

| Время | Уровень | Итог |
| --- | --- | --- |
| 0–40 | Лекция | Студент различает узел, граф, API, RMW, DDS и discovery. |
| 40–80 | Практика | Студент видит один graph и проверяет изоляцию двух domain ID. |
| 80–120 | TIAGo | Связывает общую модель с архитектурой большого робота. |

## Уровень 1: лекция (0–40)

| Минуты | Блок | Содержание и визуальная опора | Проверка |
| --- | --- | --- | --- |
| 0–5 | Проблема | Набор отдельных программ робота и необходимость связи | «Если камера и навигация независимы, как передать кадр?» |
| 5–12 | ROS 2 и узел | ROS 2 — инструменты/библиотеки; node — выполняемый компонент | Назвать 2 узла робота с разными задачами. |
| 12–19 | ROS Graph | Publisher → topic → subscribers; граф живой системы | Прочитать стрелки и тип данных. |
| 19–28 | Middleware path | ROS API → RMW → DDS implementation → transport → callback | Отнести к слою понятия RMW и DDS. |
| 28–34 | Discovery | Как участники находят друг друга; ограничения сети | Назвать две причины, почему узлы могут не обнаруживаться. |
| 34–38 | Domain ID | Логическая изоляция ROS-систем | Предсказать, увидят ли друг друга домены 40 и 41. |
| 38–40 | Итог | Связать всё с роботом | Exit ticket: нарисовать один поток и назвать слои. |

Ключевой акцент: QoS, Executor и lifecycle упомянуть, но разбирать в будущих занятиях.

## Уровень 2: практика (40–80)

Инструкция: [`../2_practice/practice-v2_06_ros_architecture_v1.md`](../2_practice/practice-v2_06_ros_architecture_v1.md).

| Время | Действие | Проверка |
| --- | --- | --- |
| 40–45 | Проверить ROS environment и RMW | `ros2 doctor --report`, `printenv RMW_IMPLEMENTATION`. |
| 45–55 | Запустить talker/listener в домене 40 | Сообщения доходят. |
| 55–62 | Посмотреть graph | `ros2 node list`, `ros2 topic list`, `rqt_graph`. |
| 62–72 | Запустить listener в домене 41 | В домене 41 chatter от talker домена 40 не приходит. |
| 72–77 | Вернуть единый домен | Listener домена 40 получает сообщения. |
| 77–80 | Очистить процессы/daemons | Оба узла завершены, будущим упражнениям не мешают. |

Не демонстрировать как закон природы, что разные RMW всегда несовместимы. Изоляция здесь проверяется через Domain ID при одинаковом RMW.

## План Б

- Если `rqt_graph` не запускается, использовать `ros2 node list` и схему talker/listener.
- Если изоляция не проявилась из-за daemon/env, остановить учебный daemon и повторить на чистых терминалах; иначе разобрать ожидаемый результат на схеме.
- Если TIAGo не работает, показать конфигурацию/README как статический архитектурный кейс.
