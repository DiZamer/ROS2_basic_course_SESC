# Занятие 8 — план lecture-v2: Node, Executor и callbacks

Содержание: [`lecture-v2_content_08_node_v1.md`](lecture-v2_content_08_node_v1.md). Слайды: [`../1_slides/lecture-v2_slides_08_node_v1.md`](../1_slides/lecture-v2_slides_08_node_v1.md).

## Цель занятия

Студент создаёт минимальный timer node в пакете, собирает и запускает его, затем отличает работающий процесс от файла исходного кода.

## Подготовка

- Общий Dev Container Jazzy открыт; package creation/build работает.
- Подготовить терминал с `ros2 node list/info`.
- Уровень 3 — TIAGo Humble уже собран/запущен либо есть статический граф и README.
- Презентация рассчитана на 40 минут; практика использует отдельный пакет `timer_demo_pkg`.

## Сетка 40+40+40

| Время | Уровень | Ожидаемый результат |
| --- | --- | --- |
| 0–40 | Лекция | Студент понимает, что создаёт Node и какую работу выполняет Executor. |
| 40–80 | Практика | `heartbeat_node` печатает heartbeat раз в секунду. |
| 80–120 | TIAGo | Узлы со своими ответственностями обнаружены и классифицированы. |

## Уровень 1 — лекция

| Минуты | Блок | Содержание | Проверка |
| --- | --- | --- | --- |
| 0–5 | Вопрос | Как один процесс обработки датчика будет реагировать на новые события? | Студент формулирует идею узла. |
| 5–12 | Node | Работающий компонент, имя, зона ответственности | Отличить source file от running node. |
| 12–19 | Callback | Функция-обработчик события; timer как простое событие | Что запускает callback? |
| 19–27 | Executor/spin | Ожидание и вызов готовых callbacks | Что будет без `spin()`? |
| 27–33 | Lifecycle | init → create/register → spin → destroy/shutdown | Расположить шаги по порядку. |
| 33–37 | Fast callbacks | Зачем не блокировать event handler долгой работой | Назвать симптом медленного callback. |
| 37–40 | CLI | `node list` и `node info` как наблюдение работающей системы | Найти имя узла. |

## Уровень 2 — практика

Инструкция: [`../2_practice/practice-v2_08_node_v1.md`](../2_practice/practice-v2_08_node_v1.md).

| Время | Действие | Контроль |
| --- | --- | --- |
| 40–45 | Проверить workspace/overlay | `ros2 pkg list` работает в контейнере. |
| 45–52 | Создать `timer_demo_pkg` через `ros2 pkg create` | Скелет сгенерирован CLI. |

| 75–78 | Проверить `ros2 node list/info` | Видно имя узла и текущие интерфейсы. |

## Уровень 3 — TIAGo

| Время | Действие | Вопрос студенту |
| --- | --- | --- |
| 80–86 | `ros2 node list` (если робот уже запущен) | Какие компоненты являются отдельными узлами? |
| 86–98 | Посмотреть `ros2 node info` 2–3 узлов | Какую задачу выполняет каждый? Какие интерфейсы видны? |
| 98–108 | Сопоставить узлы с группами | Base, navigation, sensors, simulation. |
| 108–115 | Обсудить независимое завершение узла | Что можно наблюдать, если процесс завершить в отдельной тестовой сессии? |
| 115–120 | Итоговая схема | Один subsystem → несколько nodes. |

Не останавливать основные процессы TIAGo в общей симуляции. Если нужен тест завершения узла, только на копии/изолированной учебной сессии с инструктором.
