# Зачёт 1 (занятие 12, этап 1)

## Цель зачёта

Проверить понимание архитектуры ROS2 и продемонстрировать наработки по домашнему роботу. Охватывает темы 6–11: ROS2 и middleware, workspace, node, topic, service, action.

> Источник заданий — [`lectures_content.md`](lectures_content.md), раздел «Задания для зачётов», подраздел «Зачёт 1».

## Что проверяется

| Тема | Что студент должен уметь |
| --- | --- |
| 6. ROS2 и middleware | Объяснить путь сообщения через RMW/DDS/discovery |
| 7. Workspace | Показать структуру workspace, создать пакет, собрать `colcon build` |
| 8. Node | Запустить узел, объяснить `spin()` и callbacks |
| 9. Topic | publisher/subscriber, `ros2 topic` |
| 10. Service | server/client, `ros2 service call` |
| 11. Action | server/client, goal/feedback/result/cancel, `ros2 action` |

## Задания на понимание архитектуры

Каждое задание студент выполняет индивидуально в контейнере уровня 2 (`.devcontainer/`, ROS2 Jazzy).

### Задание 1. Путь сообщения от publisher к subscriber

Объяснить на схеме путь сообщения от publisher к subscriber через RMW/DDS/discovery.

- Что принять: RMW, DDS, discovery, узел с publisher, узел с subscriber.
- Ключевые моменты: publisher и subscriber находят друг друга через discovery, обмен через DDS, RMW — слой между ROS2 API и реализацией DDS.
- Форма: схема на доске/листе с подписями + устное объяснение.

### Задание 2. Три механизма связи

Перечислить базовые механизмы связи (topic, service, action) и сказать, когда какой нужен.

- Что принять: названы три механизма; для каждого приведён пример и критерий выбора.
- Ключевые моменты: поток данных — topic; короткий запрос-ответ — service; длительная задача с прогрессом и отменой — action.

### Задание 3. Система из 2–3 узлов в rqt_graph

Запустить в контейнере уровня 2 рабочую систему из 2–3 узлов и показать её в `rqt_graph`.

- Что принять: узлы запущены (например, `sensor_node` → `monitor_node`), граф открыт, студент объясняет связи.
- Проверка: `rqt_graph` показывает узлы и topic.

### Задание 4. Executor и spin()

По готовому фрагменту кода объяснить, где Executor вызывает callbacks и что делает `spin()`.

- Что принять: студент указывает callbacks (timer, subscription, service, action) и объясняет, что `spin()` запускает цикл обработки событий.
- Ключевые моменты: `spin()` блокирует узел и раздаёт события; без `spin()` callbacks не вызываются.

### Задание 5. Пакет за отведённое время

Создать пакет, собрать его `colcon build` и запустить узел за отведённое время.

- Что принять: `ros2 pkg create`, добавление узла (простой publisher или «hello»-узел), `colcon build`, `ros2 run`.
- Ограничение по времени: 15 минут.

## Демонстрация наработок по домашнему роботу

Студент показывает собственную модель робота из `~/my_robot/` (задания [`../2_homework/`](../2_homework/)):

- **Структура workspace и пакетов** — показать `ros2_ws/src/`, пакет `my_robot_base`, где узлы и `setup.py`.
- **Работающий узел и интерфейсы** — продемонстрировать хотя бы один topic, service и action:
  - topic `/sensor_data` (`hw_09`),
  - service `/sensor_enable` (`hw_10`),
  - action `/mission` (`hw_11`).
- **Объяснение архитектуры** — какие подсистемы робота намечены и какие интерфейсы между ними (по `diary.md` и [`hw_06_ros_architecture.md`](../2_homework/hw_06_ros_architecture.md)).

## Критерии оценки («зачтено с оценкой»)

Каждое из 5 заданий оценивается 0–2 балла, демонстрация — 0–10 баллов. Итого 20 баллов.

| Задание | Баллы |
| --- | --- |
| 1. Путь publisher → subscriber | 0–2 |
| 2. Три механизма связи | 0–2 |
| 3. Система в `rqt_graph` | 0–2 |
| 4. Executor и `spin()` | 0–2 |
| 5. Пакет за время | 0–2 |
| Демонстрация домашнего робота | 0–10 |

Шкала:

| Баллы | Оценка |
| --- | --- |
| 17–20 | зачтено (отлично) |
| 13–16 | зачтено (хорошо) |
| 10–12 | зачтено (удовлетворительно) |
| 0–9 | не зачтено |

Обязательные условия: демонстрация домашнего робота выполнена (показан работающий узел и хотя бы один topic, service и action), иначе оценка не выше «удовлетворительно».
