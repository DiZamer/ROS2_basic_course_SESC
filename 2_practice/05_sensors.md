# Практика: датчики — виртуальные и реальные сенсоры

## Цель

Через 5–10 минут студент перечисляет, какие данные дают сенсоры, видит подключённые устройства глазами Linux (`lsusb`, `ls /dev`, `i2cdetect`), и сравнивает виртуальный сенсор с реальным по типу данных.

## Предварительные требования

- Открыт Dev Container уровня 2 (`.devcontainer/`, Ubuntu 24.04 + ROS2 Jazzy).
- ROS2 не устанавливается на хост — всё выполняется внутри контейнера.
- Статья [`../2_knowledge/sensors.md`](../2_knowledge/sensors.md) — прочитана.

## Что получится

- Таблица «датчик → данные → частота» своими словами.
- Вывод `lsusb` и `ls /dev`: студент находит файлы устройств.
- Сравнение: виртуальный и реальный сенсор дают один и тот же тип данных.

## Шаг 2. USB-устройства: `lsusb`

```bash
# если утилиты нет — поставить
sudo apt install -y usbutils

# список USB-устройств
lsusb
```

Что искать: камеры (часто `Webcam`/`Camera`), USB-адаптеры последовательного порта (появляются как `CP210x`, `CH340`, `FTDI`), USB-лидары. Реальный датчик, подключённый по USB, обязательно появится в этом списке.

## Шаг 3. Файлы устройств: `ls /dev`

```bash
ls /dev
```

Linux показывает устройства как файлы. Полезные имена:

- `ttyUSB0`, `ttyACM0` — последовательные порты (лидар, плата через USB);
- `video0`, `video1` — камеры;
- `i2c-1`, `i2c-2` — шины I2C.

В контейнере без проброшенного железа эти файлы могут отсутствовать — это нормально. Они появятся, когда реальный датчик подключён к машине или проброшен в контейнер.

## Шаг 4. Шина I2C: `i2cdetect`

```bash
# установить утилиты I2C
sudo apt install -y i2c-tools

# список шин I2C
i2cdetect -l

# просканировать шину 1 (если она есть в выводе выше)
i2cdetect -y 1
```

`i2cdetect -y 1` печатает таблицу адресов: каждое непустое поле — датчик, подключённый к шине I2C (например, IMU, датчик расстояния, барометр). Если шин нет — выводится ошибка; на реальном Raspberry Pi шины присутствуют.

## Шаг 5. Сравнить виртуальный и реальный сенсор

Ответьте на вопросы:

1. Реальный лидар измеряет расстояние лазером, виртуальный считает пересечение луча со стеной в симуляции. Чем отличаются их **данные** для потребителя?
2. Какая строка в описании сенсора Gazebo задаёт частоту? (подсказка: `<update_rate>`)
3. Если заменить реальную камеру на виртуальную, нужно ли менять программу, которая читает изображение?

Ответ на вопрос 3 — «нет»: тип данных одинаковый. В этом смысл виртуальных сенсоров.

| Действие | Ожидаемый результат |
| --- | --- |
| Заполнена таблица из шага 1 | 4 датчика → данные → частота без грубых ошибок |
| `lsusb` | список USB-устройств (в контейнере может быть коротким) |

## Типичные ошибки

| Симптом | Причина | Исправление |
| --- | --- | --- |
| `lsusb: command not found` | Не установлен пакет `usbutils` | `sudo apt install -y usbutils` |
| `i2cdetect: command not found` | Не установлен пакет `i2c-tools` | `sudo apt install -y i2c-tools` |
| `i2cdetect -y 1` — ошибка «No such file or directory» | В контейнере нет шины I2C | Это нормально: шины есть на реальном Raspberry Pi |
| Путают `lsusb` и `ls /dev` | Не понимают разницу «устройство» vs «файл устройства» | `lsusb` — список устройств, `ls /dev` — файлы, через которые с ними работают |
| Ждут, что в контейнере видны датчики робота | Железо не проброшено в контейнер | Датчики видно там, где они физически подключены |

## План Б: если нет GUI/симуляции

Если симуляцию запустить нельзя, разберите типы данных датчиков по документации. Ниже — поля стандартных сообщений ROS2 (полный разбор — на занятии 9, здесь только чтобы увидеть структуру данных):

| Сенсор | Тип данных ROS2 | Ключевые поля |
| --- | --- | --- |
| LiDAR | `sensor_msgs/msg/LaserScan` | `ranges[]` (дальности), `angle_min`/`angle_max`, `range_min`/`range_max` |
| Камера | `sensor_msgs/msg/Image` | `height`, `width`, `encoding`, `data[]` (пиксели) |
| IMU | `sensor_msgs/msg/Imu` | `orientation`, `angular_velocity`, `linear_acceleration` |

Задание: сопоставьте каждое поле с физической величиной (например, `ranges[]` — это расстояния, которые измеряет лидар). Это и есть «данные», которые сенсор отдаёт потребителю.
