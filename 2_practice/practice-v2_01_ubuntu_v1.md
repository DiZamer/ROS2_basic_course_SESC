# Практика-v2 01: Ubuntu и командная строка

> Уровень 2 занятия 1. Все упражнения выполняются в общем Dev Container курса (Ubuntu 24.04). ROS 2 на хост не устанавливается.

## Цель

За 40 минут студент научится определять контекст shell, работать с каталогами и файлами, запускать свой скрипт, находить программу через `PATH`, использовать справку и безопасно подготовить учебный SSH-ключ.

## Что получится

- каталог `~/cli_practice` с проверенным скриптом;
- понимание текущего пути и прав пользователя;
- найденная команда через `command -v`;
- временная пара SSH-ключей, у которой виден только fingerprint и публичная часть.

## Предварительные требования

- Открыт Dev Container уровня 2.
- VS Code terminal подключён к контейнеру.
- На уровне 3 будет отдельная среда TIAGo Humble; команды ROS 2 не выполняются на хосте.
- SSH-подключение к другой машине выполняется только при наличии учебного адреса от преподавателя.

## Шаг 1. Проверить, где и от чьего имени работает терминал (5 минут)

```bash
pwd
whoami
hostname
```

Ожидаемый результат: команды показывают текущий каталог, пользователя контейнера и имя машины/контейнера. Если `whoami` возвращает `root`, сообщите преподавателю и не выполняйте команды изменения файлов.

## Шаг 2. Создать структуру и изучить пути (8 минут)

```bash
mkdir -p ~/cli_practice/inbox
cd ~/cli_practice
pwd
touch inbox/notes.txt
ls -la
ls -la inbox
```

Ожидаемый результат: каталог `inbox` и файл `notes.txt` находятся под `~/cli_practice`.

Попробуйте абсолютный путь и переход домой:

```bash
cd /tmp
pwd
cd ~
pwd
```

## Шаг 3. Создать и запустить скрипт (7 минут)

```bash
cd ~/cli_practice
printf '#!/usr/bin/env bash\nprintf "hello robot\\n"\n' > hello_robot.sh
ls -l hello_robot.sh
chmod u+x hello_robot.sh
./hello_robot.sh
```

Ожидаемый результат: сначала у файла нет execute-бита владельца; после `chmod u+x` команда печатает `hello robot`.

## Шаг 4. Найти программу и помощь (5 минут)

```bash
command -v bash
printf '%s\n' "$PATH"
help cd
ls --help
```

Ожидаемый результат: `command -v bash` показывает путь к bash; встроенная команда `cd` описана через `help`, а внешняя `ls` — через `--help`.

Если установлен `man`, выполните `man ls` и выйдите клавишей `q`. Если `man` отсутствует, продолжайте по `--help`.

## Шаг 5. Права и граница sudo (5 минут)

```bash
ls -l hello_robot.sh
sudo -n true
```

`sudo -n true` проверяет, можно ли выполнить команду без интерактивного пароля; ничего не устанавливает и не меняет. Если политика контейнера требует пароль или запрещает sudo, остановитесь и сообщите преподавателю.

Не запускайте весь shell через `sudo` и не редактируйте системные каталоги.

## Шаг 6. Временная SSH-пара ключей (8 минут)

Используйте отдельное временное имя, чтобы не тронуть существующий ключ:

```bash
key_dir="$(mktemp -d /tmp/ssh_lab.XXXXXX)"
ssh-keygen -t ed25519 -N "" -f "$key_dir/course_lab_ed25519"
ssh-keygen -lf "$key_dir/course_lab_ed25519.pub"
cat "$key_dir/course_lab_ed25519.pub"
stat -c '%a %n' "$key_dir/course_lab_ed25519"
```

Ожидаемый результат: fingerprint выведен; публичный ключ имеет окончание `.pub`; приватный файл не выводился и не копируется в репозиторий. Переменная `key_dir` действует в этом же терминале; для необязательного подключения используй тот же терминал.

После необязательного соединения удали только созданную в этом упражнении временную пару:

```bash
rm -f "$key_dir/course_lab_ed25519" "$key_dir/course_lab_ed25519.pub"
rmdir "$key_dir"
unset key_dir
```

### Опционально: подключиться к учебному SSH-хосту

Если преподаватель выдал учебное имя пользователя, хост и заранее добавил публичный ключ, используйте предоставленные параметры. Не подключайтесь к случайному адресу и не загружайте ключ в общий репозиторий.

```bash
read -r -p "Учебный пользователь: " ssh_user
read -r -p "Учебный хост: " ssh_host
ssh -i "$key_dir/course_lab_ed25519" -o IdentitiesOnly=yes "$ssh_user@$ssh_host"
```

Введите параметры, выданные преподавателем. Если учебного хоста нет, этап подключения пропускается; модель соединения разбирается на схеме.

## Итоговая проверка

| Проверка | Ожидаемый результат |
| --- | --- |
| `pwd` в `~/cli_practice` | Путь заканчивается на `/cli_practice`. |
| `./hello_robot.sh` | Печатает `hello robot`. |
| `command -v bash` | Возвращает путь к исполняемому bash. |
| `ls -l hello_robot.sh` | Видно право `x` у владельца. |
| `ssh-keygen -lf "$key_dir/course_lab_ed25519.pub"` | Fingerprint публичного учебного ключа (до шага очистки). |

## Вопросы студенту

1. Чем отличаются `pwd`, `cd` и `ls`?
2. Что делает `PATH`?
3. Почему перед `rm` полезно выполнить `pwd` и `ls`?
4. Какой файл можно передать на сервер, а какой нужно хранить у себя?

## Типичные ошибки

| Симптом | Причина | Исправление |
| --- | --- | --- |
| `./hello_robot.sh: Permission denied` | Не установлен execute-бит | `chmod u+x hello_robot.sh`. |
| `command not found` | Команды нет в образе или она вне PATH | `command -v`, `echo "$PATH"`, проверить имя команды. |
| `ssh-keygen` предлагает перезаписать ключ | Выбран существующий файл | Отменить и выбрать новое имя. |
| `sudo -n true` завершается ошибкой | Политика контейнера не разрешает sudo без пароля | Не обходить политику; позвать преподавателя. |
| `man` не найден | Руководства не установлены в минимальном образе | Использовать `--help` или `help`. |

cp inbox/notes.txt inbox/notes_copy.txt
