# Практика-v2 03: первый проверяемый запрос к OpenCode

> Уровень 2 занятия 3. OpenCode — отдельный инструмент разработки; ROS 2 не устанавливается на хост и не нужен для этой практики.

## Цель

За 40 минут студент проверяет CLI и конфигурацию доступа, задаёт ограниченный read-only вопрос в тестовой папке, проверяет ответ по файлам и подтверждает, что исходная папка курса не изменилась.

## Что получится

- сформулирован запрос с целью, контекстом, ограничением и проверкой;
- получен ответ с указанием файлов;
- студент сверил хотя бы один факт вручную;
- приватные данные не переданы агенту.

## Предварительные требования

- OpenCode установлен и подключён к провайдеру согласно инструкции курса.
- Открыт проект курса и доступен файл `opencode.jsonc`.
- Студент понимает, что доступ агента зависит от выбранного агента и конфигурации permissions.
- Упражнение выполняется в отдельной тестовой папке; не запускайте Build на TIAGo.

## Шаг 1. Проверить CLI (5 минут)

```bash
opencode --version
opencode --help
```

Ожидаемый результат: OpenCode печатает версию и справку. Если команда не найдена, перейти к плану Б и не устанавливать программу самостоятельно без инструкции преподавателя.

## Шаг 2. Прочитать настройки доступа (7 минут)

Откройте `opencode.jsonc` и найдите:

- `instructions` — какие проектные файлы передаются как инструкции;
- `agent` — какие агенты настроены в этом проекте;
- `permission.edit` и `permission.bash` — как управляются изменения и команды.

Запишите ответ: «Какие действия разрешены без подтверждения? Какие требуют подтверждения? Какие запрещены?»

Не копируйте в чат токены, API-ключи и содержимое секретных переменных.

## Шаг 3. Создать безопасную тестовую папку (5 минут)

В отдельной терминальной сессии:

```bash
mkdir -p ~/opencode_lab
cd ~/opencode_lab
printf '# Lab note\n\nRobot: differential-drive base.\nSensor: LiDAR.\n' > README.md
printf 'This folder is for a read-only OpenCode exercise.\n' > scope.txt
sha256sum README.md scope.txt
```

Если папка уже содержит вашу работу, выберите новое имя, например `~/opencode_lab_2`.

## Шаг 4. Составить проверяемый запрос (5 минут)

В ответе должны быть: назначение робота по README, использованный файл, запрет на изменения. Пример текста запроса:

```text
Прочитай только README.md и scope.txt в текущей папке.
Кратко назови тип базы и сенсор.
Ничего не редактируй и не запускай shell-команды.
В конце укажи, из какого файла взят каждый факт.
```

## Шаг 5. Запустить запрос через Plan/режим анализа (8 минут)

Перед запуском убедитесь, что текущая рабочая папка — `~/opencode_lab`, а эффективные права агента не разрешают неожиданное изменение. Если настройки неясны, покажите запрос преподавателю и выполните разбор на подготовленном ответе.

```bash
opencode run --agent plan "Прочитай README.md и scope.txt в текущей папке. Назови тип базы и сенсор, укажи источник каждого факта. Ничего не меняй и не запускай команды."
```

Ожидаемый результат: краткий ответ с фактами и именами файлов.

## Шаг 6. Проверить ответ и состояние (7 минут)

```bash
sha256sum README.md scope.txt
cat README.md
cat scope.txt
```

Сравните контрольные суммы до и после запроса. Они должны совпадать; если изменились — остановитесь и проверьте тестовую папку. Главное — сопоставить каждое утверждение с файлами, а не просто поверить ответу.

Запишите:

- какой факт совпал;
- где он подтверждается;
- что агент не проверил или не мог знать.

## Итоговая проверка

| Проверка | Успешный результат |
| --- | --- |
| OpenCode CLI | Версия и справка выводятся. |
| Конфигурация | Студент находит правила `edit` и `bash`. |
| Prompt | Ясно указаны папка, задача и запрет действий. |
| Ответ | Факты сопоставлены с исходными файлами. |
| Проект курса | Не изменён практикой. |

## Вопросы студентам

1. Что отличается между инструкцией `AGENTS.md` и permission инструмента?
2. Почему одного «ничего не меняй» недостаточно как технической гарантии?
3. Как доказать, откуда взят факт в ответе агента?
4. Что делать, если ответ выглядит уверенным, но файл его не подтверждает?

## Типичные ошибки

| Симптом | Причина | Исправление |
| --- | --- | --- |
| Агент ответил не по тем файлам | Контекст не был ограничен | Назвать папку и разрешённые файлы явно. |
| Агент предложил правку | Запускали edit-capable режим или права это разрешают | Остановить действие; повторить на тестовой папке и после проверки permissions. |
| Агент назвал несуществующий файл | Ответ модели не был подтверждён | Проверить путь через файловый менеджер или `ls`. |
| Показан секрет | В prompt вставили приватное содержимое | Не пересылать его; заменить на вымышленное значение. |

## План Б

Если модель/провайдер недоступен, студент пишет prompt на бумаге, а преподаватель выдаёт заранее подготовленный ответ. Студент проверяет его по `README.md` и помечает неподтверждённые утверждения.
