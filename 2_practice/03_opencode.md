# Практика: первый запрос к opencode

## Цель

Через 10 минут студент делает первый запрос к opencode в проекте, смотрит, какие права у агента, выполняет безопасный read-only запрос и разбирает результат.

## Предварительные требования

- opencode установлен и настроен (провайдер модели сконфигурирован через `opencode auth login`).
- Открыта папка проекта `ROS2_basic_course_SESC`.
- ROS2 не устанавливается на хост; opencode — отдельный инструмент, и в курсе он запускается на хосте (не в контейнере курса).

## Что получится

- Знание, как запускать opencode и читать его конфиг.
- Понимание прав агента из `opencode.jsonc`.
- Один выполненный read-only запрос и разобранный ответ.

## Шаг 1. Проверить opencode

```bash
opencode --version
opencode --help
opencode agent list
```

Ожидаемый результат: версия без ошибки; `agent list` показывает встроенных (`build`, `plan`, `general`, `explore`), служебных (`title`, `summary`, `compaction`) и проектных (`lecture-author`, `practice-coder`, `reviewer`) агентов.

## Шаг 2. Посмотреть права агента

Откройте [`opencode.jsonc`](../../opencode.jsonc) и найдите блок `permission`:

```jsonc
"permission": {
  "edit": "allow",
  "bash": { "*": "ask", "ls": "allow" },
  "webfetch": "ask",
  ...
}
```

Ответьте себе: что агент может делать без спроса, а что — только после вопроса? Обратите внимание на subagent-ов `lecture-author`, `practice-coder`, `reviewer` — у каждого свои права.

## Шаг 3. Безопасный read-only запрос

Для анализа без изменений используйте агента Plan. Один из вариантов:

```bash
opencode run --agent plan "Объясни структуру репозитория ROS2_basic_course_SESC: за что отвечают папки 1_lecture, 2_knowledge, 2_practice, 2_homework, 3_Robot"
```

Ожидаемый результат: агент перечисляет папки и их назначение, не изменяя файлы.

## Шаг 4. Запрос про конкретный пакет

```bash
opencode run --agent plan "Расскажи, что находится в 3_Robot/TIAgo_humble и за что отвечает его AGENTS.md"
```

Ожидаемый результат: короткое описание проекта TIAGo со ссылкой на его `AGENTS.md`.

## Шаг 5. Разобрать результат

Проверьте ответ:

- совпадает ли он с тем, что вы видите в файлах;
- не выдумал ли агент несуществующие файлы;
- на какой источник он ссылается.

Если ответ неверен или неполон, уточните запрос или откройте нужный файл и сверьте.

## Проверка результата

| Действие | Ожидаемый результат |
| --- | --- |
| `opencode --version` | печатает версию |
| `opencode agent list` | список встроенных и проектных агентов |
| чтение `opencode.jsonc` | вы можете объяснить блок `permission` |
| read-only запрос через Plan | ответ без изменений в проекте |

## Вопросы студентам

1. Чем агент Plan отличается от Build? Когда брать какой?
2. Что означает `"bash": { "*": "ask" }` в правах?
3. Зачем нужен `AGENTS.md` и что будет без него?
4. Почему для чтения кода безопаснее `@explore`, а не Build?

## Типичные ошибки

| Симптом | Причина | Исправление |
| --- | --- | --- |
| `opencode: command not found` | opencode не установлен | Установить по [официальной инструкции](https://opencode.ai/docs/) |
| Агент начал менять файлы | Работаете в Build, а не в Plan | Переключиться на Plan (Tab) или `--agent plan` |
| Агент придумал несуществующие файлы | Запрос слишком общий, агент «галлюцинирует» | Спросить про конкретный файл и сверить с `ls` |
| Нет модели/провайдера | Не выполнен `opencode auth login` | `opencode auth login` и выбрать провайдера |

## Дополнительное задание

Вызовите субагента Explore вручную через `@` в TUI и попросите найти, где в проекте упоминается `AGENTS.md`:

```text
@explore найди все файлы AGENTS.md в проекте и кратко опиши каждый
```
