# Практика: Ubuntu и командная строка

## Цель

Через 10 минут студент уверенно перемещается по файловой системе, понимает права и `sudo`, ставит пакеты через `apt`, читает справку и подключается по SSH к другой машине с разбором ошибок.

## Предварительные требования

- Открыт Dev Container уровня 2 (`.devcontainer/`, Ubuntu 24.04 + ROS2 Jazzy).
- Терминал внутри контейнера: меню VS Code → Terminal → New Terminal.
- ROS2 не устанавливается на хост — всё выполняется внутри контейнера.

## Что получится

- Знание команд навигации и работы с файлами.
- Настроенные права на файле и понимание `sudo`.
- Установленный через `apt` пакет и прочитанная справка.
- Пара SSH-ключей и рабочее SSH-подключение к другой машине (в классе — временный SSH-сервер или соседний компьютер в той же сети; запасной вариант — `ssh localhost`).

## Шаг 1. Навигация и файлы

```bash
# где я сейчас
pwd

# кто я (в контейнере — пользователь ubuntu, не root)
whoami

# создать рабочую папку и перейти в неё
mkdir -p ~/cli_practice
cd ~/cli_practice

# создать файл и посмотреть содержимое папки
touch notes.txt
ls -la
```

Ожидаемый результат: `pwd` → `/home/ubuntu`, `whoami` → `ubuntu`, `ls -la` показывает `notes.txt` и скрытые `.` / `..`.

## Шаг 2. Права и sudo

```bash
# сделать файл исполняемым (добавить x владельцу)
chmod +x notes.txt
ls -l notes.txt
# → -rwxr-xr-x 1 ubuntu ubuntu ...

# sudo — выполнить команду от имени администратора
# обновить список пакетов (нужны права root)
sudo apt update
```

Ожидаемый результат: у `notes.txt` появилось право `x`; `sudo apt update` обновляет список пакетов без запроса пароля (в контейнере настроен беспарольный sudo).

## Шаг 3. Пакеты и справка

```bash
# установить пакет tree (показывает дерево папок)
sudo apt install -y tree

# применить: показать дерево домашней папки (первые 2 уровня)
tree -L 2 ~

# справка двумя способами
tree --help
man tree    # выход из man — клавиша q
```

Ожидаемый результат: `tree` устанавливается и печатает дерево папок; `man tree` открывает руководство.

## Шаг 4. Переменные окружения и PATH

```bash
# где shell ищет программы
echo $PATH

# путь к программе bash
which bash

# задать переменную и прочитать её
export ROBOT_NAME=tiago
echo $ROBOT_NAME
```

Ожидаемый результат: `which bash` → `/usr/bin/bash`; `echo $ROBOT_NAME` → `tiago`.

## Шаг 5. SSH: ключи и подключение к другой машине

В классе подключаемся к другой машине: либо к временному SSH-серверу, который поднимает преподаватель, либо «компьютер к компьютеру» в одной сети (например, к ноутбуку соседа, где запущен SSH-сервер). Если сети нет, используйте запасной вариант — подключение к тому же контейнеру через `localhost` (описан ниже).

Сначала создаём пару ключей:

```bash
# сгенерировать ключ ed25519 без парольной фразы
ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519

# посмотреть файлы: приватный и публичный
ls ~/.ssh

# посмотреть публичный ключ (его кладут на робота/сервер)
cat ~/.ssh/id_ed25519.pub
```

Ожидаемый результат: в `~/.ssh/` появились `id_ed25519` (приватный) и `id_ed25519.pub` (публичный).

Запасной вариант без сети — поднять SSH-сервер внутри контейнера и разрешить вход по ключу:

```bash
# установить SSH-сервер (если уже стоит — apt сообщит, что всё актуально)
sudo apt install -y openssh-server

# запустить сервер (в контейнере нет systemd, поэтому service)
sudo service ssh start

# разрешить вход по нашему публичному ключу
mkdir -p ~/.ssh
cat ~/.ssh/id_ed25519.pub >> ~/.ssh/authorized_keys
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```

Запасной вариант: подключаемся к самому себе (проверяет ключ и механизм SSH, но не работу по сети):

```bash
# при первом подключении ssh спросит про отпечаток хоста — ответьте yes
ssh -o StrictHostKeyChecking=accept-new localhost

# внутри вы увидите приглашение — вы на «удалённой» машине
hostname
exit
```

Ожидаемый результат: `hostname` печатает имя контейнера, `exit` возвращает в прежний терминал.

## Проверка результата

| Команда | Ожидаемый результат |
| --- | --- |
| `pwd` | `/home/ubuntu` |
| `whoami` | `ubuntu` |
| `ls -l notes.txt` | содержит `-rwx` |
| `tree -L 2 ~` | дерево папок |
| `which bash` | `/usr/bin/bash` |
| `ssh <user>@<host>` | вход по ключу без пароля (в классе — на другую машину; запасной вариант — `ssh localhost`) |

## Вопросы студентам

1. Чем `cd` отличается от `ls`? Что делает `cd` без аргумента?
2. Зачем нужен `sudo`, если пользователь `ubuntu` и так работает в контейнере?
3. Что такое `PATH` и почему `tree` заработал только после установки?
4. Почему публичный ключ можно показывать, а приватный — нет?

## Типичные ошибки

| Симптом | Причина | Исправление |
| --- | --- | --- |
| `Permission denied` при `ssh localhost` | Публичный ключ не попал в `authorized_keys` | Повторить `cat ~/.ssh/id_ed25519.pub >> ~/.ssh/authorized_keys` и `chmod 600` |
| `Connection refused` при `ssh` | Сервер `sshd` не запущен | `sudo service ssh start` |
| `bash: tree: command not found` | Пакет не установлен или `apt` не обновил список | `sudo apt install -y tree` |
| `man tree` не работает | Пакет `man` не установлен | `sudo apt install -y man-db` |
| `ssh-keygen` перезаписал старый ключ | Повторный запуск с тем же `-f` | Перед генерацией проверяйте `ls ~/.ssh` |

## Дополнительное задание

Скопируйте файл на «удалённую» машину через `scp` и убедитесь, что он там появился:

```bash
# скопировать notes.txt в домашнюю папку по SSH
scp ~/cli_practice/notes.txt localhost:~/notes_copy.txt

# проверить, что файл появился (в той же домашней папке)
ls -l ~/notes_copy.txt
```

Ожидаемый результат: `notes_copy.txt` появляется в домашней папке.
